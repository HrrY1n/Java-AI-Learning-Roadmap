# 预测与修改练习：答案

**先完成 [predict_and_modify.md](predict_and_modify.md) 至少 6 题再打开本文件。** 预测错误的条目，重点读"为什么"而不是背结果。

## A1
```text
3 / 1
3.5
```
为什么：`7 / 2` 两个 int → 商 3 舍余；`7 % 2` 余 1。`7 / 2.0` 有 double 参与 → 小数除法。

## A2
```text
3345
```
为什么：从左到右——`1+2` 是 int 加法得 3；再遇 `"3"` 变拼接得 `"33"`；之后全是字符串拼接。

## A3
```text
012
```
改 `<=` 后：
```text
0123
```
为什么：`i < 3` 最后一轮 i=2；`i <= 3` 最后一轮 i=3。

## A4
```text
1 3 结束
```
为什么：偶数被 continue 跳过；i=5 时 break 直接终止循环——"结束"由循环后的 println 打出。continue 不会跳过 `i++`。

## A5
```text
99
```
为什么：`b = a` 复制的是数组地址，两个变量是同一段格子的两个名字。

## A6
```text
5
```
为什么：值传递。`bump` 里的 x 是副本，自增与外面无关。

## A7
```text
66
B
```
为什么：`'A' + 1` 参与算术时 char 被提升为 int（65+1=66）；强转回 char 后按字符表解读为 B。

## A8
```text
安全
```
`&&` 左边为 false 时右边**不执行**（短路），所以 `arr[2]` 的越界访问根本没发生。换成 `&`：两个操作数都会执行 → 抛 `ArrayIndexOutOfBoundsException`。这就是为什么条件判断用 `&&`/`||` 而不用单个 `&`/`|`。

## B1
变化的行为：`a / b` 从 3 变 3.333…；`a % b` 从 1 变 1.0。其余行不变。原因：b 成为 double 后，含 b 的运算全部走浮点。

## B2
90 → 60：总分减少 30（402→372 → 实际按 day05 数据 {90,85,76,100}：351→321）；平均分减少 30/4 = 7.5。笔算后与运行一致才通过。

## B3
移动后：输入 0 → 打印"程序结束。"→ break 跳出 switch → 继续循环体的后续（无）→ 回到 while → **再次打印菜单并等待输入**——程序不再退出（除非再无输入可读）。关键点：`break` 跳出的是 switch，不是 while；原版用 `return` 直接结束 main。

## B4
需要动 1 处（乘法分支内加一个 if）。若你动了 3 处以上，说明校验位置离规则太远。验证：`6 * 0` → 提示；`6 * 3` → 18.0。
