# 深化课 05：循环边界——差一错误从哪里来

对应示例：`com/javaroadmap/stage01/deepdives/loops/LoopBoundsDemo.java`

**运行后你会看到什么**：5 行输出，其中两行暴露典型边界 bug 的实际效果。看完本文你应该能在写下循环条件前，先回答"第一轮、最后一轮、步进"三个问题。

## 场景

`for (int i = 1; i < 5; i++)` 想打印 1 到 5，结果少了 5；倒计时的条件写成了 `n >= 0`，就多打一个 0。循环是程序里重复次数最多的结构，边界错一次，错误就被重复 N 次——而且往往"测试时看不出来"（数据恰好不踩边界）。

## 必须理解

写任何循环，先在注释或心里回答三个边界问题：

1. **起点**：第一轮 `i` 是几？要处理的第一个元素/数字是几？
2. **终点**：希望最后一轮 `i` 是几？`<` 与 `<=` 的选择由它决定——**`i < n` 的最后一轮是 n-1；`i <= n` 的最后一轮是 n**。
3. **步进**：`i` 每轮怎么变？步进不是 1 时，终点可能永远不被**精确踩到**（如 `i += 2` 配 `i <= 9` 的最后一轮是 8 不是 9）。

`while` 还多一条：**让循环趋于结束的那个变量，更新语句是否每轮都执行、且在正确的位置**。`while (n > 0)` 里漏掉 `n--` 就是死循环。

**心智模型**：循环条件是"闸门"，每轮进出都要过一次闸。`break` 是从侧门离场（整个循环结束），`continue` 是回到闸口重新排队（跳过本轮剩余语句，但步进/条件照常执行）。for 循环中 continue **仍然会执行 `i++`**——它跳的是循环体，不是步进。

## 理解原理：为什么差一错误这么顽固

因为"差一"在两种语义下都"看起来对"：

- 遍历下标 0..length-1 用 `i < length`；
- 遍历数字 1..n 用 `i <= n`。

两件事长得几乎一样，条件却一个用 `<` 一个用 `<=`。硬记"什么时候用 <"注定出错；**先明确终点值，再选运算符**才是可迁移的方法。

**Observe（先预测再运行）**：运行示例前，预测 5 个方法各自的输出序列；重点预测 `printEveryOther(2, 9)` 的最后一轮和 `countOneToThree` 里 continue 后 i 的值。

## 动手：修改一个条件

1. 把 `printEveryOther` 改成步进 3、范围 1..10：最后一轮是几？练一次"步进不整除区间"的预测。
2. 修复 `countdownWrong`（把 `n >= 0` 改回 `n > 0`）：输出从 `3 2 1 0` 变成什么？用一句话说明原 bug 多打了哪一轮、为什么。
3. 给 `countOneToThree` 把 `break` 改成 `continue`：发生什么？思考两者语义差异现在是否清楚。

## 常见错误

- 循环内改变边界变量（`while (i < n)` 里又改 `n`）：先确定本轮语义是否需要，再动笔。
- 双重循环内外层变量混用（`i`/`j` 交换）：编译能过，输出全错；命名时内外层用有区分度的名字。
- 死循环后不知道怎么停：终端里 `Ctrl+C` 终止程序；验证脚本里的 30 秒超时干的就是这件事。

## 独立练习

在 `my_practices/` 写 `BoundaryDrills`，三个方法各自独立完成并通过自检：

1. `printDigits(int n)`：按一行打印 n 的每一位（如 407 → `7 0 4`，倒序打印即可），n 为 0 时打印 `0`。（边界：0 是合法输入，不能什么都不打。）
2. `sumBetween(int a, int b)`：返回 a 到 b 之间所有整数的和，**不假设 a < b**（a > b 时也要正确）。
3. `fizzBuzzLimit(int n)`：1..n，3 的倍数打 Fizz、5 的倍数打 Buzz、15 的倍数打 FizzBuzz，其余打数字本身。自检 n=15 的最后一行必须是 `FizzBuzz`。

每个方法先在注释里写"起点/终点/步进"三问答，再写代码。
