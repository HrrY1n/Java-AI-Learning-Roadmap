# 深化课 04：方法参数传递——Java 只有值传递

对应示例：`com/javaroadmap/stage01/deepdives/argpassing/ArgumentPassingDemo.java`

**运行后你会看到什么**：3 行结果——number 仍是 10、scores[0] 变成 0、scores2[0] 仍是 90。看完本文你应该能对"方法里改参数，外面变不变"给出**有依据**的预测，而不是背结论。

## 场景

day06 之后你开始把逻辑拆进方法。马上遇到一个问题：`swap(a, b)` 为什么换不动外面的两个数？而另一个方法里 `arr[0] = 0` 却"生效"了？同一个语言里两种行为，最流行的解释"基本类型值传递、对象引用传递"是**错的**——这个误解会一路污染你对 Stage 02 引用的理解，现在就拆掉它。

## 必须理解

规则只有一条：**传参时，实参的值被复制一份给形参**。

- `int a = 10`：变量里存的就是 10，复制的是数值。
- `int[] arr`：变量里存的是"数组在哪"的地址，复制的**也是这个数值**——两份相同地址指向同一个数组。

所以判断"外面变不变"，只看一件事：**方法改的是地址指向的对象内容，还是形参变量本身**。

| 方法内代码 | 改了什么 | 外面看得见吗 |
| --- | --- | --- |
| `value = 999`（基本类型形参） | 形参这份副本 | 看不见 |
| `arr[0] = 0`（顺着地址改内容） | 共享的那个对象 | 看得见 |
| `arr = new int[]{...}`（换地址） | 形参这份地址副本 | 看不见 |

**心智模型**：调用方法 = 把变量内容**复印**一份递进去。基本类型的纸上写的是数；引用类型的纸上写的是门牌号。你按门牌号进门搬家具（改内容），主人回来看得见；你把纸上的门牌号涂改成本身（重新赋值），主人手里的纸没变。

## 理解原理：三个实验的递进逻辑

三个 case 是刻意设计的证明链，值得按顺序复述：

1. **case1 建立基线**：改形参，外面不变——所有人都接受。
2. **case2 制造错觉**：改数组元素，外面变了——"看！对象是引用传递！"这个错觉正是本课要抓的错误直觉。
3. **case3 决定性反驳**：如果真是引用传递，`arr = 新数组` 应该同步改变调用方变量；实际没有。说明复制的是**地址值**本身，而不是"引用的别名"。

如果 case3 让你停顿了一下，恭喜——那正是误解所在的位置。

**Observe（先预测再运行）**：合上示例的注释，只看 main 里的三行 println，先写下预测，再运行核对。

## 动手：修改一个条件

1. 在 case2 的方法里加一行 `arr = new int[]{5, 5};` 放在 `arr[0] = 0;` **之前**：外面变不变？和 case3 的结论是否自洽？
2. 写一个 `trySwap(int a, int b)`：方法内交换形参。调用后打印两个实参验证你的预测（结果：换不动；原因是每个形参只是独立副本）。

## 常见错误

- "传对象就是引用传递"：case3 的反例已经否定。
- 以为"看得见"和"看不见"是两种传递机制：机制只有值传递一种，差别在**复制的值是什么**。
- 因此得出"方法改不了任何外部状态"：恰恰相反，顺着地址改对象内容是常态——这提示我们设计方法时要**明确约定**哪些副作用是故意的（Stage 02 的封装会把它变成受控操作）。

## 独立练习

在 `my_practices/` 写 `PassingPredictor`：不运行，先在注释里写出下面 4 段代码各自调用后 `data[0]` 与 `x` 的值；然后实现并运行核对，每错一处写一句"我当时的错误模型是什么"。

```text
a) int x = 5;            bump(x);                       // bump: x = x + 1
b) int[] data = {5};     bumpFirst(data);               // bumpFirst: arr[0] = arr[0] + 1
c) int[] data = {5};     replace(data);                 // replace: arr = new int[]{9}
d) int[] data = {5};     bumpThenReplace(data);         // 先 arr[0]++ 再 arr = new int[]{9}
```
