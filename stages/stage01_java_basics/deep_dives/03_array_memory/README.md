# 深化课 03：数组、下标与内存——为什么下标从 0 开始

对应示例：`com/javaroadmap/stage01/deepdives/arrays/ArrayMemoryDemo.java`

**运行后你会看到什么**：5 行输出；取消一行注释后运行会崩溃并打印 `ArrayIndexOutOfBoundsException: Index 4 out of bounds for length 4`。看完本文你应该能解释"下标为什么从 0 开始"并写出不越界的循环。

## 场景

数组是 Stage 01 后半程的主角，也是最多"看起来会了、一写就错"的地方：越界崩溃、`length` 与最大下标差一、空数组时 `scores[0]` 直接崩溃。这些错误的根源是同一个——对"数组在内存里是什么"没有具体图像。

## 必须理解

**心智模型**：数组是一段**连续的格子**。变量 `scores` 存的不是这些格子，而是"这段格子从哪里开始"的**地址**。访问 `scores[i]` 的真实含义是：

```text
起点地址 + i × 每格大小   ← 这就是"下标从 0 开始"的原因
```

`i` 是**偏移量**：离起点偏移 0 格是第一个元素，所以第一个元素是 `scores[0]`，最后一个元素的偏移是 `length - 1`。C 语言祖师爷的选择延续到了 Java；它不是"习惯问题"，而是"偏移语义"的直接结果。

**合法下标范围是 `[0, length - 1]`，`length` 本身永远越界**。`length` 是数组自带的元信息（像格子墙上的标牌），不属于任何格子。

## 理解原理

越界不会在编译期被发现——编译器只查语法类型，不追踪你的 `i` 运行到几。越界发生在运行期，JVM 主动抛出 `ArrayIndexOutOfBoundsException` 并**终止程序**。它不是玄学惩罚，而是一种保护：C 语言不检查越界，会静默改写相邻内存，产生更难查的 bug。

**边界写法对照**（示例第 5 段）：

```java
for (int i = 0; i < scores.length; i++)   // 推荐：边界即语义"i 是合法下标"
for (int i = 0; i <= scores.length - 1; i++)  // 等价但绕
for (int i = 1; i < scores.length; i++)   // 错：漏掉第一个元素（常见于"求最大值时"误用）
for (int i = 0; i <= scores.length; i++)  // 错：最后一次越界
```

**Observe（先预测再运行）**：预测 5 行输出；取消越界那行的注释重新编译运行，把报错信息完整抄在笔记里——`Index 4 out of bounds for length 4` 两个数字分别是什么含义。

## 动手：修改一个条件

1. 把数组改为长度 0：`int[] scores = {};`——运行后哪一行先崩溃？为什么"空数组求最大值"需要单独处理（这正是阶段练习里"边界：空数组"的由来）。
2. 把 `another[0] = 0` 那段改为再打印 `another.length`：两个变量的 `length` 是否一致？说明 length 存在哪段格子上。

## 常见错误

- 用 `scores.length` 当最后一个元素：差一。
- 求最大值时把 `max` 初始化为 0：遇到全负数（如温度）就错；正确做法是初始化为 `scores[0]`（空数组另行处理）。
- 循环里同时修改 `length` 语义：数组长度不可变，但"有效元素个数"可以小于 length（后续用计数器区分，Stage 03 的 List 会替你管理这件事）。

## 独立练习

在 `my_practices/` 写 `ArrayBoundsQuiz`：定义长度 5 的 int 数组，用循环从 `scores.length - 1` 递减到 0 **倒序**打印所有元素；然后写第二个循环，故意让它越界一次，运行并把异常信息抄进注释。最后回答：如果把倒序循环写成 `for (int i = scores.length; i >= 0; i--)`，第一个访问的下标是多少？会立刻发生什么？
