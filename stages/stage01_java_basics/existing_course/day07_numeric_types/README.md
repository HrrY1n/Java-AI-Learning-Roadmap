# 数值类型、提升窄化与溢出边界

> 对应示例：`com/javaroadmap/stage01/day07numerictypes/App.java`

## 八种基本数据类型总表

Java 共有 8 种基本（原始）数据类型——**不是 6 种数值类型就结束了**。每一种都是大小固定的内存格子：

| 分类 | 类型 | 位宽 | 取值范围 / 说明 | 默认字面量与后缀 |
| --- | --- | --- | --- | --- |
| 整型 | `byte` | 8 位 | `-128 ~ 127` | 整数字面量默认按 `int` 读 |
| 整型 | `short` | 16 位 | `-32,768 ~ 32,767` | — |
| 整型 | `int` | 32 位 | 约 `±21 亿`（`-2^31 ~ 2^31 - 1`） | 无后缀即 `int`（可用 `2_100_000_000` 下划线分隔） |
| 整型 | `long` | 64 位 | 约 `±9.22 × 10^18` | 超过 `int` 范围**必须**加 `L`（建议统一大写 `L`） |
| 浮点 | `float` | 32 位 | 单精度 IEEE 754（约 6~7 位有效十进制） | **必须**加 `f`/`F` 后缀 |
| 浮点 | `double` | 64 位 | 双精度 IEEE 754（约 15~16 位有效十进制） | 小数字面量默认是 `double` |
| 字符 | `char` | 16 位 | `0 ~ 65,535` 无符号 UTF-16 码元 | 单引号如 `'A'`（码值 65，可参与算术） |
| 布尔 | `boolean` | — | 只有 `true` / `false`（**不与 0/1 互通**） | `true` / `false` |

## 两条让新手困惑的类型转换规则（JLS §5.2 / §5.6）

### 1. 编译期常量窄化：为什么 `byte b = 127;` 合法而 `byte sum = x + y;` 报错？

- 当右边是一个**编译期已知值且在目标范围内**的常量字面量（如 `byte b = 127;`），Java 编译器在编译期就能确定不会丢数据，因此允许隐式窄化赋值。
- 一旦右边是**变量或非常量表达式**（如 `int n = 127; byte b = n;`），哪怕运行前你知道它装得下，编译器也只认变量类型 `int`，直接报“从 int 转换到 byte 可能有损失”。

### 2. 二元算术的整型提升

`byte`、`short`、`char` 只要参与 `+ - * / %` 等二元算术运算，在运算开始前就会被**先提升为 `int`**（JLS §5.6.2）。因此：

```java
byte x = 10, y = 20;
int ok = x + y;       // 正确：x + y 的结果类型是 int
// byte err = x + y;  // 编译错误：试图把 int 塞回 byte
```

同理，这也是预测题 A7 中 `'A' + 1` 得到 `66`（`int`）而不是 `'B'`（`char`）的根本原因。

## 整数溢出 vs 浮点特殊值

| 异常情境 | 整型 (`int` / `long`) | 浮点 (`float` / `double`) |
| --- | --- | --- |
| 超出最大值 | **静默补码绕回**（如 `Integer.MAX_VALUE + 1 == Integer.MIN_VALUE`） | 溢出为 `Infinity` / `-Infinity` |
| 除以 `0` | 抛出 `ArithmeticException: / by zero` | `1.0 / 0.0` 得 `Infinity`；`0.0 / 0.0` 得 `NaN`（不抛异常） |
| 精度损失 | 整数不会有小数误差 | 二进制无法精确表示十进制 `0.1`，`0.1 + 0.2 == 0.30000000000000004` |

工程需要“溢出就立刻报错而不是悄悄绕回成负数”时，使用 JDK 8+ 提供的 `Math.addExact(a, b)`、`Math.multiplyExact(a, b)`，溢出时直接抛出 `ArithmeticException`。

## 学习验收与自我检核

- **需要掌握什么**：说全 8 种基本类型及其字面量默认规则；区分“编译期常量窄化”和“变量赋值拦截”；理解算术时的整型提升；知道整数溢出静默绕回而浮点会产生 `Infinity`/`NaN`。
- **如何证明理解**：① 不用 IDE 就能判断 `byte c = a + b;` 与 `long x = 9000000000;` 为何编译失败；② 独立写出用 `int` 与 `long` 分别算 `13!` 的实验并指出溢出步；③ 说明 `Math.addExact` 与普通 `+` 的适用差异。
- **什么情况属于尚未掌握**：认为“数字太大程序就会自己报错”；或以为 `float` 只是比 `double` 范围小而没意识到 `0.1 + 0.2` 两者都不适合算钱。
- **针对错误如何复习**：截断与精度误区去对照深化课 `deep02`（`02_integer_division`）；溢出行为去预测题 `A9` 验证。
