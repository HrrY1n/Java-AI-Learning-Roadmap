# 条件分支：决策顺序、短路规则与 switch 边界

> 对应示例：`com/javaroadmap/stage01/day03ifswitch/App.java`

## 业务规则与决策树

程序处理输入时，同一份数据往往要根据业务规则走不同的逻辑分支。Java 提供两套结构：`if / else if / else`（适合区间判断、多条件组合）与 `switch`（适合对单个离散值按枚举分支选择入口）。

```text
if-else（互斥区间，顺序敏感）            switch（离散值精确跳转）
  从上到下找第一个 true                    按表达式值直接命中对应 case
  命中后其余分支全部跳过                   遇到 break 或 -> 结束（否则继续往下"贯穿"）
```

## 必须弄清的三条规则

### 1. `if-else` 的条件顺序遮蔽陷阱

`if-else` 只会执行**第一条满足条件**的分支。如果把范围更宽的条件放在前面，窄条件将永远没有机会被执行：

```java
// 错误写法：score = 95 也满足 >= 60，直接输出"及格"，"优秀"变成死代码！
if (score >= 60) {
    System.out.println("及格");
} else if (score >= 90) {
    System.out.println("优秀");
}
```

写多段区间分支时，**要么按从严到宽（从大到小）排列，要么把区间上下界显式写全**。

### 2. 短路求值（`&&` / `||` vs `&` / `|`）

逻辑运算符 `&&` 与 `||` 是**短路**的：只要左边已经能决定整个表达式的真假，右边**根本不会求值**。

- `count > 0 && total / count >= 60`：当 `count == 0` 时左边为 `false`，整个 `&&` 必为 `false`，右边的 `total / count` 被直接跳过，不会触发除零 `ArithmeticException`。
- 若误写成单个按位/逻辑运算符 `&`（非短路），两边表达式都会先求值，除零立刻发生。这正是工程里判空保护 `str != null && str.length() > 0` 成立的前提。

### 3. `switch` 的支持类型与 JDK 版本演进

`switch` 不是任意类型都能传（如 `double`/`float`/`boolean` 都不支持）。

| Java 特性 | 支持的表达式类型 | 穿透行为 |
| --- | --- | --- |
| 传统 `switch (x) { case 1: ... break; }` | `byte`/`short`/`char`/`int`（含对应包装类）、`enum`、**`String`（Java 7 起）** | 默认会"贯穿"到下一个 `case`，**必须手动加 `break` 或 `return`** |
| `switch` 箭头语法（**Java 14+ 正式引入**） | 同上（Java 21+ 还支持模式匹配） | `case 1 -> ...` 执行完自动结束，**不会贯穿**，更安全 |

## 常见错误对照

- **忘记 `break` 导致贯穿**：传统写法里 `case 1:` 末尾漏写 `break;`，即使条件是 `1` 也会接着把 `case 2:` 的代码一起跑掉。
- **用 `==` 比较两个 `String`**：`switch` 对 `String` 底层按内容比较（传统 `switch(str)` 遇到 `str == null` 会抛 `NullPointerException`；Java 21+ 的模式 `switch` 可用 `case null` 显式接住空值，未写 `case null` 时仍按具体规则抛出该异常）；但在 `if` 里比较两个字符串是否内容相等，必须用 `.equals()`，不能用 `==`（Stage 02 深入解释引用与对象）。

## 学习验收与自我检核

- **需要掌握什么**：能够根据规则结构选择 `if-else` 或 `switch`；写出无条件遮蔽的区间分支；利用 `&&`/`||` 短路保护前置条件；知道传统 `switch` 必须配 `break` 及其对 `null` 敏感（Java 21+ 模式 `switch` 可用 `case null` 显式处理空值）。
- **如何证明理解**：① 不运行就能画出输入 `score = 95`、`day = 1` 去掉 `break` 后的完整执行路径；② 能解释为什么 `count > 0 && total / count >= 60` 在 `count == 0` 时安全而换成 `&` 崩溃；③ 独立写出一个带合法性前置检查的月份转季节或年龄分段程序。
- **什么情况属于尚未掌握**：只会模仿现成 `if` 模板，把 `score >= 60` 排在 `>= 90` 前发现不了逻辑错误；或见到 `switch` 中漏了 `break` 误以为只会执行命中的一个分支。
- **针对错误如何复习**：遮蔽问题回看本节规则 1 并调换示例顺序实测；短路问题去预测题 A8 对照 `&&` 与 `&` 的运行结果。
