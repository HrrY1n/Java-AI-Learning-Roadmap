## 练习 1：删除学生

**任务背景**：管理员发现录错学生，需要按 id 删除。删除是"找不到"的高发区：不存在、重复删、非法 id 三种情况都必须有明确结果，不许崩溃。

- **初始名单**（源码中固定）：`1:张三/88`、`2:小红/95`、`3:小刚/55`。
- **菜单功能**（Scanner 循环，每轮先打印一行 `1=删除 2=名单 0=退出` 再读选项）：
  1. 删除：下一行读 id。`id <= 0` 打印 `id 非法：<id>`；名单里有 → 打印 `已删除：<id>` 并真正移除；没有 → 打印 `学生不存在：<id>`。
  2. 名单：打印 `学生名单：[1:张三/88, 3:小刚/55]`（格式 `[<id>:<姓名>/<分数>, ...]`，逗号后一个空格，按当前顺序）。
  3. `0` 打印 `程序结束。` 并退出；其他选项打印 `没有这个选项。`。
- **语义约束**："不存在"用返回 false 的思路处理（打印失败消息），**不许抛异常**——用异常设计深化课的三分法说明理由。

**正常示例**：删 2 → `已删除：2` → 名单只剩 1 和 3。
**边界示例**：删除后**再次**删除 2 → `学生不存在：2`。
**错误输入（必须处理）**：id 为 `0` 或 `-1` → `id 非法：<id>`；id `99` → `学生不存在：99`。

**验收条件**
- [ ] 正常、边界、错误输入各运行一遍，行为符合预期。
- [ ] 重复删除、删除不存在的 id 都不崩溃、不改变其余数据。
- [ ] 能回答：为什么"不存在"打印失败消息而不是抛异常？

**需要独立思考的部分**：用下标遍历删还是用迭代器/`removeIf`？for-each 循环里直接 `remove` 会发生什么（预测题 S03A6）？写出你的选择。

## 练习 2：修改分数

**任务背景**：成绩更正是高频操作。同一个"改分"入口有三种失败原因，失败消息必须能区分——否则用户和排错的人都不知道哪里错了。

- **初始名单**（源码中固定，与练习 1 相同）。
- **菜单功能**（每轮打印 `1=改分 2=及格名单 0=退出`）：
  1. 改分：先读 id，再读新分数（**两行总是都读完**，再按顺序校验——否则非法 id 会让分数行错位到下一轮菜单）。校验顺序：`id <= 0` → `id 非法：<id>`；查无此人 → `学生不存在：<id>`；分数不在 0~100 → `分数必须在 0 到 100 之间：<分数>`；全部通过 → `已更新：<id> 新分数：<分数>` 并真正改值。
  2. 及格名单：打印 `及格名单：[张三/88, 小红/95]`（分数 >= 60，按名单顺序，格式 `[<姓名>/<分数>, ...]`）。
  3. `0` → `程序结束。`；其他 → `没有这个选项。`

**正常示例**：把 2 的分数改为 95 → `已更新：2 新分数：95`，及格名单里小红是 95。
**边界示例**：改 0 与 100 都必须成功（边界值合法）。
**错误输入（必须处理）**：id `-1`、id `999`、分数 `150`——三种失败消息**精确不同**。

**验收条件**
- [ ] 三种错误输入得到三种不同的失败消息。
- [ ] 修改成功后，及格名单随之变化（改 3 的分数为 60 后，小刚进入及格名单）。
- [ ] 校验逻辑集中在一处，没有复制粘贴到两个方法里。

**需要独立思考的部分**：分数校验放在入口、还是放在"学生"对象里（构造/设置时拒绝）？两种位置各挡住了什么？写出取舍。

## 练习 3：优秀名单双版本

**任务背景**：教务要一份优秀名单（分数 >= 90）。同一份名单用 Stream 和普通 for 各实现一遍，是检验"你真的懂 Stream 在做什么"的镜子。

- **数据**：源码中两个平行数组 `String[] names` 与 `int[] scores`（下标一一对应）。
- **任务**：
  1. 用 **Stream** 实现 `listExcellentStream()`：filter + map/collect，不使用外部可变变量。
  2. 用普通 **for** 实现 `listExcellentFor()`：与 Stream 版语义完全等价。
  3. main 依次打印两版结果，格式：`Stream 版：[小红, 小雪]`、`for 版：[小红, 小雪]`（`[<姓名>, ...]` 按原数组顺序；空名单打印 `[]`，不许打印 null）。

**正常示例**：names `{张三,小红,小刚,小雪}`，scores `{88,95,55,90}` → 两版都是 `[小红, 小雪]`（**边界 90 必须入选**）。
**边界示例**：全部低于 90 → 两版都是 `[]`。
**错误输入**：空数组 → 两版都是 `[]`。

**验收条件**
- [ ] 两版输出一致，`>= 90` 的边界语义两版相同。
- [ ] Stream 版没有外部可变变量（对照 Lambda/Stream 深化课的副作用纪律）。
- [ ] 用一句话写清：这个需求你最终会提交哪一版，为什么。

**需要独立思考的部分**：`filter`、`map`、`collect` 各对应 for 版的哪几行？把对应关系写进注释。

## 练习 4：email 持久化（CSV 解析）

**任务背景**：学生档案要加 email，文件格式从 `id,name,score` 升级为 `id,name,score,email`。解析外部数据的第一课：**单行坏数据不能拖垮整个仓库**。

- **任务**：从标准输入逐行读取（读到输入结束），每行逗号分隔 `id,name,score,email`：
  - 恰好 4 个字段且 id、score 都能解析为整数 → 打印 `读取：<id>:<姓名>/<分数>/<email>`（email 为 `-` 时原样打印 `-`）。
  - 字段数不是 4，或 id/score 解析失败 → 打印 `坏行：<原始行内容>`（先 trim 行首尾空白再输出原文）。
  - 全部行处理完后打印 `共 <成功数> 条，坏行 <坏行数> 条`。
- **约束**：每行先去掉首尾空白，逗号分隔后**每个字段再去一次空白**；每行独立解析——一行失败只影响这一行；数字解析用 `Integer.parseInt` 并捕获 `NumberFormatException`。

**正常示例**：`3,小刚,82,gang@school.cn` → `读取：3:小刚/82/gang@school.cn`。
**边界示例**：`4,小明,90,-` → email 原样为 `-`；行尾带空格的行 trim 后正常解析。
**错误输入（必须处理）**：`5,小红`（字段不足）与 `abc,小红,90,-`（id 非数字）都计入坏行，程序继续处理后续行。

**验收条件**
- [ ] 一条坏行 + 两条好行的输入：读入 2 条，坏行有明确提示，程序不崩溃。
- [ ] 能说出：坏行选择"跳过并提示"还是"整体报错"，理由是什么（异常设计深化课三分法）。
- [ ] `split(",", -1)` 与 `split(",")` 在"尾部字段为空"时的差异你能解释。

**需要独立思考的部分**：email 字段需要校验格式吗？本题允许任何非空值——如果要求"必须含 @"，解析策略要怎么改？

## 渐进提示（卡住才看，逐级解锁）

### 练习 1：删除学生

- **L1 理解问题**：删除 = 找到 → 移除 → 给出明确结果；三种结果（非法 id / 成功 / 不存在）互不重叠。
- **L2 相关知识**：`List.remove(int index)` 与 `remove(Object)` 的重载陷阱见预测题 S03A2；边遍历边删的坑见 S03A6。
- **L3 结构思路**：学生用一个小类或 `Map<Integer, String>` 都可以；先写 `deleteById(int)` 返回 boolean，main 只做菜单分发与消息打印。
- **L4 调试线索**：删错人 → 下标与 id 混淆；重复删除报"已删除" → 删除后没有真正从容器移除；遍历时删崩溃 → 回看 S03A6 的三种安全写法。

### 练习 2：修改分数

- **L1**：修改 = 定位 + 校验 + 覆盖；三种失败消息必须能区分原因。
- **L2**：失败消息带上下文（id、越界值）；`>=60` 与及格名单的边界口径要一致。
- **L3**：先查 id 合法性，再查存在性，最后查分数范围；通过后先改数据再打印确认消息。
- **L4 调试线索**：改完名单没变 → 你 new 了新对象但没放回容器；消息千篇一律 → 每个失败分支没带上下文；150 被接受 → 范围判断写成了 `< 101` 以外的口径。

### 练习 3：优秀名单双版本

- **L1**：同一份名单两种范式；先写 for 版（你熟），再翻译成 Stream。
- **L2**：`filter` 保留"分数 >= 90"的下标；`collect(Collectors.toList())` 收尾；空结果 collect 出来就是 `[]`。
- **L3**：`IntStream.range(0, names.length)` 或先把两个数组 zip 成小对象，二选一；for 版注意空数组直接返回空列表。
- **L4 调试线索**：两版名单不同 → 边界写成了 `> 90`；Stream 版编译不过 → 泛型推断失败，检查 lambda 参数类型；打印 null → 忘了空名单的兜底。

### 练习 4：email 持久化（CSV 解析）

- **L1**：CSV 一行 = 一个学生的序列化；解析循环里每一行自成一个事务。
- **L2**：`split(",", -1)`（保留尾部空字段）、`String.trim()`、`Integer.parseInt` 抛 `NumberFormatException`。
- **L3**：读一行 → trim → split → 字段数校验 → 逐字段解析（数字解析单独 try）→ 成功打印 / 失败计入坏行；坏行判断集中在一个私有方法里。
- **L4 调试线索**：`ArrayIndexOutOfBoundsException` → 字段数没校验就取 email 下标；数字解析异常冒泡 → 你没接住 NumberFormatException；坏行打印了 trim 前的原文 → trim 和取原文的顺序反了。
