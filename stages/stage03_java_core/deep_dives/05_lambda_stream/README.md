# 深化课 05：Lambda 与 Stream——"描述要什么"而不是"一步步怎么拿"

对应示例：`com/javaroadmap/stage03/deepdives/lambdastream/LambdaStreamDemo.java`

**运行后你会看到什么**：4 行输出，其中第 3 段的标题之后**没有任何"经过"输出**——那是惰性求值的现场证明。看完本文你应该能解释"中间操作为什么不执行"，并判断一段数据加工该用循环还是 Stream。

## 场景

`StudentService.listPassedStudents()` 里有一段 `.stream().filter(...).collect(...)`。day02 的写法（for + if）和它做同一件事。如果没有心智模型，你会"会写 Stream 但读不懂、不敢改"。本课把两个模型立起来：**Lambda 是可传递的行为；Stream 是惰性流水线**。

## 必须理解

**Lambda 的本质**：`(a, b) -> a.length() >= b.length() ? a : b` 是"一个方法的方法体"，它的类型是**只有一个抽象方法的接口**（函数式接口，如 day01 的 `Calculator`）。所以 Lambda 不是新语法机制，是老接口的简写——接口定义"形状"，Lambda 填充"内容"。

**Stream 的三段式**：

```text
数据源 . 中间操作(0..n，返回 Stream，惰性) . 终止操作(恰好 1 个，触发执行)
```

中间操作只是"记账"：把"要过滤、要转换"记在流水线上，**一个元素都不处理**；终止操作（`collect`、`forEach`、`anyMatch`…）一调用，整条链才开工。示例第 3 段只有中间操作，所以 `peek` 什么都没打印——这不是 bug，是设计。

**心智模型**：普通循环是"你自己站在传送带边逐个搬"；Stream 是"给工厂下订单：把 A 车间的货筛掉次品、贴上标签、装箱给我"。订单先评审（编译检查类型），投产在接单时（终止操作）。

## 理解原理：什么时候用循环，什么时候用 Stream

| 场景 | 更合适 | 原因 |
| --- | --- | --- |
| 一层"筛选→转换→收集/聚合" | Stream | 意图直接可读，无中间变量 |
| 需要下标、需要提前 break、边遍历边改结构 | 普通 for | Stream 表达这些要么别扭要么根本不允许 |
| 两层以上嵌套 + 复杂状态 | 普通 for | 强行 Stream 会把逻辑切碎，可读性倒退 |

**副作用纪律**：Stream 的每个环节应当"进一个出一个"，不修改外部变量。`forEach` 里 `count++` 这类写法是"用 Stream 外形写循环逻辑"，两头不占。判断标准：**把 lambda 体换成方法引用后仍说得通，才适合 Stream**。

**Observe（先预测再运行）**：预测 4 行输出（第 3 段的 peek 要有把握地写"无输出"）；预测把第 2 段的 `collect(...)` 整行删掉后编译器报什么？（真实答案：不兼容的类型——中间操作链的产物仍是 `Stream<String>`，不能赋给 `List<String>`；这本身就是"中间操作惰性"的类型证据。）

## 动手：修改一个条件

1. 在第 2 段的 `filter` 与 `map` 之间插入 `.peek(n -> System.out.println("处理到：" + n))`：观察输出顺序——是"全部过滤完再全部转换"，还是"每个元素走完全程"？这能直接验证"逐元素流过流水线"的真实模型。
2. 把第 2 段改写为等价的 for 循环，贴在旁边对照：哪版更短？哪版更容易在中间加一个 `if` 提前退出？

## 常见错误

- 对同一数据源二次使用同一个 Stream 对象：终止过一次就作废，会抛 `IllegalStateException`。
- 在 `filter/map` 的 lambda 里打印或改外部状态：破坏惰性模型，调试时行为诡异（需要观察时用 `peek`，且明白它只为调试存在）。
- 以为 Stream 提升了性能：单线程下它通常与循环相当；**用它是为了可读性**，并行流（`parallelStream`）属于 P1 且有前提。

## 独立练习

在 `my_practices/` 写 `ScoreQueries`：给定 `List<Student>`（name, score，写死 5 条），分别用 **Stream 与普通 for 两种方式**实现：① 及格名单；② 平均分；③ 最高分学生姓名（多个并列时返回任意一个并在注释说明）。自检：两版输出一致；③ 用 Stream 时不借助外部可变变量。
