# 预测与修改练习：答案

**先完成 [predict_and_modify.md](predict_and_modify.md) 至少 5 题再打开本文件。**

## A1
```text
明仔
```
`s2 = s1` 复制引用（地址），两个变量是同一个对象。

## A2
```text
false
true
```
`==` 比较引用（是否同一个对象）——两次 `new` 生成两个对象；`equals` 比较内容。顺带：`String a = "Java"; String b = "Java";` 时 `==` 为 true（字面量常量池复用），但这属于"记住有这回事"，判断依据永远优先用 equals。

## A3
```text
0 / null
```
`int` 是基本类型，默认 0；`String` 是引用类型，默认 null（"没有指向任何对象"）。这也是"未初始化就使用"系列 bug 的来源。

## A4
调用 `Dog` 的 `eat`。编译时：编译器检查 `Animal` 有没有 `eat`（有才编译通过）；运行时：JVM 看对象**实际类型**是 Dog，动态绑定到 Dog 的版本。

## A5
```text
A 诞生
B 诞生
```
子类构造器第一行隐式 `super()`——先完成父类部分的初始化，再执行子类构造器体。显式写了 `super(...)` 就不再隐式补。

## B1
输出顺序跟着**调用顺序**走，与类定义顺序无关。多态决定"调谁的版本"，不决定"什么时候调"。

## B2
`withdraw(99999)` 直接把余额扣成负数——程序不报错，但账户进入非法状态。被破坏的约定是"余额不允许为负"；这条规则原来的家就在被删的那行 if 里。教训：**删校验=删除规则**，规则必须写在类内某个明确位置。

## B3
在 `service.add(new Student("老王", 150))` 一行抛 `IllegalArgumentException`，程序终止；第 4 行统计**不会**打印。因为异常沿调用链上抛，main 无人处理 → JVM 打印堆栈并退出。

## B4
改动点应为 1 处（deposit 方法内加一个 if）。`deposit(50)` 无提示；`deposit(1001)` 打印大额提示且余额照常增加——提示不改变业务结果，这是"通知"与"校验"的区别。
