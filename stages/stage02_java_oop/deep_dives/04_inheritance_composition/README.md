# 深化课 04：继承与组合——"是什么"才继承，"有一个"就组合

对应示例：`com/javaroadmap/stage02/deepdives/inheritance/InheritanceCompositionDemo.java`

**运行后你会看到什么**：3 组输出，其中第 2 组暴露正方形继承长方形的经典事故。看完本文你应该能对任意两个类判断"该继承还是该组合"，并说出理由。

## 场景

"继承能复用代码"是初学 OOP 最危险的半句话。day04 的 `Dog extends Animal` 语法 5 分钟就会了，判断"什么时候**不该**用"却需要本课。用错继承的系统会越长大越僵硬：父类改一行，不相干的子类集体出错。

## 必须理解

两种关系回答两个不同的问题：

- **继承（extends）**：表达"**是一个**"。`Dog` 是一个 `Animal`，所以任何需要 `Animal` 的地方都可以放 `Dog`，且行为不变得诡异。
- **组合（字段）**：表达"**有一个**"。`Car` 有一个 `Engine`，车不是引擎——把引擎当字段装进来，只暴露"drive"这类车辆功能。

**判据（里氏替换的朴素版）**：子类对象必须能替换父类对象，**不破坏父类的行为约定**——包括那些没写进代码的隐含约定（比如"setWidth 不影响 height"）。

**心智模型**：继承是"承接全部承诺"，组合是"按需租用能力"。承诺接得起才接；只想用别人几个功能时，租（组合）比继承整个家族（连带继承所有不相关的方法与约束）轻得多。

## 理解原理：正方形为什么是反面教材

数学上"正方形是长方形"为真；代码里 `Square extends Rectangle` 后：

1. 调用方拿到 `Rectangle rect = new Square(5)`，按长方形的约定调用 `setWidth(4)`，**默认约定是 height 不变**（没写出来，但所有 Rectangle 使用者都这么预期）；
2. `Square` 为了维持自身不变量（四边相等）必须在 `setWidth` 里偷偷改 height；
3. 结果：`rect.area()` 返回 16 而不是约定中的 20——**替换父类后行为被破坏**。

问题不在"数学分类"，在**行为约定**。继承审核的是行为，不是词汇上的"是不是"。

**什么时候继承是对的**：子类是父类的真子集行为 + 需要多态（下一课）。`Dog extends Animal` 之所以健康：Animal 的每个使用者对"act() 会做点什么"没有更细的预设，Dog 的行为不违约。

**Observe（先预测再运行）**：预测 1) 2) 3) 的输出；重点第 2 组——如果你是"拿到 Rectangle 引用的调用方"，这个结果算不算 bug？为什么错不在 Square 的代码，而在"这段关系"本身？

## 动手：修改一个条件

1. 把 `Square` 的 `setWidth` 修复逻辑删掉：不越界了，但产生"宽 4 高 5 的正方形"——另一种违约。体会：正方形继承长方形**两头堵**，正确做法是不要这层继承。
2. 给 `Car` 换引擎：`new Car(new Engine())` 改成传入一个 `start()` 返回"电动马达启动"的对象——如果 Engine 是接口，这里就是多态；先体验"组合让部件可替换"。

## 常见错误

- 为了复用几行工具方法而继承（`Utils` 有个方法我想要 → extends）：组合或直接调用才对。
- 继承层次超过两三层还在加深：出问题时一层层 super 追溯，可读性崩塌。
- 忘了 `super(...)` 或在子类构造器里重复父类初始化：先理解 `super(name)` 是"把父类那部分出生流程跑完"。

## 与后面学习的联系

- 继承的正当归宿是**多态**（下一课）：`Animal a = new Dog(...)` 才是继承存在的理由，代码复用不是。
- "组合优先"在 Stage 03 里直接体现为：`StudentService` **拥有一个** `StudentRepository` 字段，而不是继承某个"可存储"基类。
- 接口是比类继承更轻的"承诺"，下一课把两者放在一起比较。
