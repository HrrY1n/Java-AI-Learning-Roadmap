# 深化课 01：引用与对象状态——两个变量"是同一个对象"

对应示例：`com/javaroadmap/stage02/deepdives/refstate/ReferenceStateDemo.java`

**运行后你会看到什么**：6 行输出，其中 `a.score = 95` 与第 6 行 `传参改字段后 a.score = 99，姓名仍是 = 小明` 是核心观察点。看完本文你应该能预测"改一个对象变量，另一个受不受影响"、看懂方法传参为什么"改字段生效而重新 new 无效"，并解释 `==` 与内容比较的区别。

## 场景

day01 建了 `Student` 对象并赋字段。接下来写 `StudentService` 时会频繁地把对象传来传去——放进列表、当参数、当返回值。如果不确定"我现在改的是副本还是本体"，就会写出一堆"看起来生效了，数据却没变"或"莫名其妙被别人改了"的 bug。这个知识点是 OOP 一切行为的地基。

## 必须理解

**对象本体住在堆内存里，变量里存的是指向它的引用句柄**（可以直观类比为门牌号；底层 GC 整理内存时可能会搬移对象物理地址，JVM 会同步更新引用句柄，因此上层始终看到“指向同一对象”的稳定语义）。

由此三个推论覆盖绝大多数场景：

1. `b = a` 复制的是地址——此后 `a`、`b` 是**同一个对象的两个名字**，不是两份拷贝。
2. 通过任何一个名字改字段，另一个名字立刻"看见"。
3. `==` 比较的是地址（同一扇门）；比较**内容**要用字段对比或 `equals`。

**心智模型**：变量是写着门牌号的纸条。复印纸条不会复印房子。想"复制一份学生"，必须**显式新建对象**并逐字段赋值——这个动作叫复制，Java 不会替你隐式做。

## 理解原理：与参数传递是同一件事

Stage 01 [深化课 04](../../../stage01_java_basics/deep_dives/04_argument_passing/README.md) 的 case3（方法里 `arr = 新数组` 不影响外面）就是本课第二段的现象：**给变量重新赋值，只是换掉这张纸条上的门牌号，不影响其他纸条，更不影响旧房子**。

把两条规则合起来，读任何对象代码都可以自问两问：

- 这一步是"换门牌"（赋新对象）还是"进门改东西"（改字段/调方法）？
- 我手里这张纸条，还有谁拿着同款？

**Observe（先预测再运行）**：预测 6 行输出。重点第 1 行——为什么改的是 `b.score`，`a.score` 却变了？

## 动手：修改一个条件

1. 在第三段后加 `a = null;` 再打印 `a.score`：得到 `NullPointerException`。null 的含义是"这张纸条上没有门牌"——顺着没有门牌的纸条进门当然失败。读一遍报错堆栈，定位到行号。
2. 给 `sameContent` 换成比较两个**不同内容**的学生，确认返回 false：手写字段比较是为将来理解 `equals` 重写做铺垫。

## 常见错误

- 以为 `new Student(同名同分)` 与原对象"相等"：`==` 是 false——地址不同。
- 集合里 add 后又改原对象，以为集合里是快照：集合里存的也是门牌号，改的就是同一个对象。
- 把"复制对象"寄希望于赋值：需要副本时必须显式 `new` + 复制字段。如果对象内部只含基本类型或不可变对象（如 `String`），逐字段拷贝就是独立副本；如果对象内部还包含另一个可变对象/数组（如 `Student` 里有一个 `int[] scores`），只把内部引用赋给新对象叫**浅拷贝**（两个对象的数组依然共用！），连内部可变对象一起重新 `new`/`.clone()` 才叫**深拷贝**。
- 空指针陷阱：比较对象字段（例如 `sameContent`）时，直接写 `x.name.equals(y.name)` 会在 `x.name == null` 时抛 `NullPointerException`，应优先使用 `Objects.equals(x.name, y.name)`（内部先判 `==` 与 `null`）。
