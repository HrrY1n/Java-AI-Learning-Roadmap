# 深化课 02：构造方法与 this——对象如何带着合法状态出生

对应示例：`com/javaroadmap/stage02/deepdives/constructorthis/ConstructorThisDemo.java`

**运行后你会看到什么**：两次 `姓名：…，年龄：…`；取消注释的第三段会抛 `IllegalArgumentException`。看完本文你应该能说清 `new` 一步背后发生的三件事，以及 `this` 的准确含义。

## 场景

day02 的写法是 `new Person("小明", 18)`——但如果没有构造器，`new Person()` + 逐字段赋值的写法允许"先造出一个 name=null 的半成品"，任何人在半成品上调用方法都会出错。**构造器把"对象从一开始就完整、合法"变成类的责任，而不是每个使用者的自觉**。

## 必须理解

**`new Person("小明", 18)` 依次做三件事**：

1. 按类定义分配一块内存（此时所有字段是默认值：0、false、null）；
2. 找到**参数匹配**的那个构造器并调用，构造器里的赋值覆盖默认值；
3. 返回新对象的**地址**（结合上一课：赋给变量的是门牌号）。

**没有写构造器时**，编译器送一个"无参、什么都不做"的默认构造器；**一旦你写了任何构造器，默认的就没有了**——这就是"写了有参构造器后 `new Person()` 编译报错"的原因。

**this 的准确含义**：`this` 是"**当前这次调用/初始化所针对的那个对象**"。它只有两种高频用途：

- 在构造器/方法里区分**同名的字段与参数**（`this.name = name`）；
- 在方法里显式指明"操作的是调用者的字段"（`this.rename(...)` 中的 this 运行时指向调用者）。

**心智模型**：构造器是产线的质检工序，this 是传送带上"当前这个工件"的代词。质检不合格就当场退回（抛异常），坏产品不会流入市场。

## 理解原理：为什么把关要在构造器里

对象一旦出生，它的字段可能被任何持有引用的代码修改（上一课的别名问题）。**把关越靠近出生时刻，非法状态存活的时间越短**。构造器校验是"防御的最早时机"；彻底的控制要到下一课封装（private 字段）才能实现——那时所有修改入口都被收拢，校验才真正无法绕过。

**Observe（先预测再运行）**：① 注释掉构造器里 age 校验那三行，取消 main 第三段注释——输出什么？② 恢复校验再运行——报错发生在 `new` 这一行还是 `show()` 这一行？先预测再验证，这能检验你是否真的理解"构造在 new 时执行"。

## 动手：修改一个条件

1. 再加一个构造器 `Person(String name)`，用 `this(name, 0)` 调用另一个构造器（this 的第三种用法：构造器间委托）。注意它必须是构造器第一行。
2. 把字段 `int age` 改成 `Integer age` 再新建对象并**在构造器赋值前打印它**（临时加一行）：观察 null 与 0 的区别——为 Stage 03 的 `Integer`/`int` 话题埋一个钩子。

## 常见错误

- 写了有参构造器却还想要无参用法：需要就显式再写一个无参构造器。
- `this.name = name` 写成 `name = name`：参数给自己赋值，字段仍是 null——不报错但完全无效，是最高频的构造器 bug。
- 在构造器里做重活（IO、复杂计算）：构造器只负责"把状态立起来"；耗时操作放到显式方法里。

## 独立练习

在 `my_practices/` 写一个 `Rectangle` 类：两个构造器（宽高 / 只给宽=正方形），校验边长必须 > 0（否则抛 `IllegalArgumentException`），提供 `area()`、`perimeter()`、`show()`。自检：`new Rectangle(3, 4)` 面积 12；`new Rectangle(-1)` 抛异常；`new Rectangle()` 编译失败并解释原因。
