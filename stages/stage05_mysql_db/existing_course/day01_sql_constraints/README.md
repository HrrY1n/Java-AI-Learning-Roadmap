# SQL 基础、数据类型与数据库约束

> 对应示例：`day01_sql_constraints/App.java` · SQL 脚本：`sql/01_constraints.sql` · 目标版本：**MySQL 8.0+**

## 1. 为什么不能一直把数据存进 CSV 文本文件？

在 Stage 03 的 `FileStudentRepository` 中，每次增加或删除一名学生都必须“把整个文本文件重新读进内存、改完后再整份覆盖写回”。这在真实后端下很快会撞上四堵墙：
1. **并发写冲突**：两条线程或两个进程同时改文件会互相覆盖；
2. **约束脆弱**：CSV 本身不拒绝“学号重复”、“成绩 999”或“缺姓名”——坏行靠 Java 临时兜底；
3. **局部查询慢**：只查一个 `id` 也得读取整份文件；
4. **缺少原子性**：写到一半掉电会留下损坏的半截文件。

关系型数据库（MySQL + InnoDB 存储引擎）把**并发、约束、索引查找与事务原子性**下沉到专业存储引擎中解决。

## 2. MySQL 8.0 常用字段类型对照

| Java 类型 | MySQL 推荐类型 | 选型理由与踩坑提醒 |
| --- | --- | --- |
| `int` / `long` | `INT` / **`BIGINT`** | 主键与累计计数首选 `BIGINT`（防 Stage 01 讲过的 21 亿溢出） |
| `String` | `VARCHAR(N)` / `TEXT` | 变长字符串；注意 **`utf8mb4`**（MySQL 里历史 `utf8` 实际是 `utf8mb3` 只有 3 字节，存不了 emoji 与部分生僻字；**MySQL 8.0 起默认字符集才改为 `utf8mb4`**） |
| 金额 | **`DECIMAL(10, 2)`**（或存“分”的 `BIGINT`） | **绝不用 `FLOAT`/`DOUBLE` 存金额**，避免二进制浮点舍入误差 |
| 时间 | `DATETIME` / `TIMESTAMP` | 业务时间常用 `DATETIME`（不受 2038 年 32 位上限与会话时区隐式转换干扰） |

## 3. 五类核心约束：让脏数据进不了库

1. **`PRIMARY KEY`（主键）**：唯一标识一行（非空且不重复），在 InnoDB 中决定整行数据按主键物理聚集存放；单表通常使用自增代理键 `BIGINT AUTO_INCREMENT`。
2. **`NOT NULL`**：禁止缺失值（`NULL` 在 SQL 里代表“未知”，连 `= NULL` 都不成立，必须写 `IS NULL`）。
3. **`UNIQUE KEY`**：允许业务键不重（如学号 `student_no`），违约时 MySQL 抛出错误码 **`1062`**（SQLState `23000`）。
4. **`CHECK`**：**MySQL 版本硬差异**——在 MySQL 5.7 及 8.0.15 之前，`CHECK` 语句会被静默解析并**完全忽略**；**直到 MySQL 8.0.16 才真正强制执行**（违约抛错误码 **`3819`**）。在老版本或复杂规则中仍需应用层与触发器配合。
5. **`DEFAULT`**：提供安全缺省值（如 `CURRENT_TIMESTAMP`）。

> 为什么应用层校验了还要在数据库层加约束？——**防御纵深**：任何后台脚本、直连 SQL、并发请求或另一套微服务写库时都会受同一套数据库约束保护。

## 学习验收与自我检核

- **需要掌握什么**：解释为什么用数据库代替 CSV；选对 `BIGINT`/`VARCHAR`/`DECIMAL`/`utf8mb4`；说清主键、唯一键与 `CHECK` 的作用及 MySQL 8.0.16 版本界线。
- **如何证明理解**：① 能连本地隔离 MySQL 跑通 `01_constraints.sql` 与 `day01_sql_constraints/App.java` 并解释错误码 `1062` 与 `3819`；② 能手写一张含代理主键、唯一编码、非空姓名与价格大于 0 的商品表 DDL。
- **什么情况属于尚未掌握**：认为“在 Java 写了 `if (score < 0)` 就不用给表加约束”；或用 `utf8` 与 `DOUBLE` 建金额表。
- **针对错误如何复习**：Java 凭据读取机制读 `DbEnv.java`；数值类型与精度对比回看 Stage 01 `day07`。
