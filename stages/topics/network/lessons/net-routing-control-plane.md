# 控制平面：链路状态、距离向量、OSPF/BGP 与 SDN

## 1. Scenario：从一个具体问题出发
一条链路故障后流量绕行；你不知道路由表何时更新。

## 2. Why：为什么这个问题值得系统理解
转发是每包动作；路由是全网信息收敛过程，二者共同决定可达性与收敛时间。

## 3. Concept：核心概念
链路状态算法让节点了解全网拓扑；距离向量逐步交换估计。OSPF 常用于自治系统内部，BGP 连接 ISP。SDN 将控制逻辑集中。

## 4. Mental Model：把机制装进一张图
`拓扑/邻居信息 -> 算法收敛 -> 路由表 -> 数据平面转发`。

## 5. Minimal Code：最小示例
```text
router -> neighbor update -> SPF/DV 计算 -> forwarding table
```

## 6. Observe：先预测，再运行
先手算一个小图：节点 A-B-C-D，边 A-B=1、B-C=2、A-C=5、C-D=1、B-D=4。从 A 出发写出 Dijkstra 每一轮确定的最短节点与距离，得出最短路径树；完成练习中的实现后再用它核对结果。

## 7. Modify：只改一个有意义的条件
删掉边 B-C 后重算同一张图，观察 A 到 C、D 的路径如何绕行；这正是链路故障后路由重新收敛的缩影。

## 8. Exercise：独立完成
实现教学版 Dijkstra，输入节点/边，输出最短路径；明确标注不是真实 OSPF 实现。

## 9. Real Usage：联系 Java 与工程实践
多云网络、服务网格和跨可用区部署都受路由收敛影响。
