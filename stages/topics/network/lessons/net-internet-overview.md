# 因特网概览：分组、时延与分层

## 1. Scenario：从一个具体问题出发
打开网页偶尔很慢；你不知道瓶颈在客户端、服务器、链路还是协议。

## 2. Why：为什么这个问题值得系统理解
现代后端排错需要先定位延迟来源：传输、排队、处理、传播或应用处理。

## 3. Concept：核心概念
因特网由端系统、链路、交换机和 ISP 组成；分组交换复用链路。时延包括处理、排队、传输和传播。分层模型把复杂性拆成可替换服务。

## 4. Mental Model：把机制装进一张图
`应用 -> 传输 -> 网络 -> 链路 -> 物理`；每一层只依赖下层服务。

## 5. Minimal Code：最小示例
```text
浏览器 -> HTTP -> TCP -> IP -> 以太网/Wi-Fi -> 物理链路
```

## 6. Observe：先预测，再运行
用 `ping 127.0.0.1` 与访问外网对比回环和实际链路的 RTT 差异；不要把 `ping` 当作 HTTP 性能。

## 7. Modify：只改一个有意义的条件
把本地服务器响应加入人为延迟，观察客户端总时间是否主要来自应用处理。

## 8. Exercise：独立完成
画一张请求路径图，标注 DNS、TCP、TLS、HTTP 各自可能出现的延迟。

## 9. Real Usage：联系 Java 与工程实践
API 超时、重试策略和容量估算需要区分网络层与应用层时间。
