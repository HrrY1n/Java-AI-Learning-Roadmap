# 网络安全：机密性、完整性、TLS 与端点保护

## 1. Scenario：从一个具体问题出发
HTTPS 已经加密，为什么还要校验证书、控制权限和日志？

## 2. Why：为什么这个问题值得系统理解
网络安全需要同时满足机密性、完整性、可用性和身份鉴别；不同层保护不同威胁。

## 3. Concept：核心概念
对称加密保护数据，公钥加密交换密钥；MAC 与签名保证完整性；TLS 在传输层提供安全通道。防火墙和 IDS 处理边界与入侵检测。

## 4. Mental Model：把机制装进一张图
`身份鉴别 -> 密钥协商 -> 加密/完整性 -> 记录日志/响应`。

## 5. Minimal Code：最小示例
```java
SSLContext context = SSLContext.getDefault();
System.out.println(context.getProtocol());
```

## 6. Observe：先预测，再运行
查看 JVM 默认 SSL 协议名称；不要用自签名证书绕过生产校验。

## 7. Modify：只改一个有意义的条件
为本地 HTTPS 服务配置受信任证书，观察握手与证书校验差异。

## 8. Exercise：独立完成
设计一个 HTTPS 客户端检查清单：证书、协议版本、超时、重试和敏感日志。

## 9. Real Usage：联系 Java 与工程实践
API 安全、支付和内部服务调用都要区分传输安全、业务鉴权与审计。
