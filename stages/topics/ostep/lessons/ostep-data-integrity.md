# 数据完整性：校验和与保护

## 1. Scenario：从一个具体问题出发
读取多年前的备份发现某字节错了，但文件系统没有报错。

## 2. Why：为什么这个问题值得系统理解
介质可能静默损坏；完整性保护需要检测甚至纠正。

## 3. Concept：核心概念
校验和检测常见讹误，奇偶校验可纠正单比特错误；布局要避免元数据与数据同时损坏。Java 可用 CRC32 做完整性检查，不是加密签名。

## 4. Mental Model：把机制装进一张图
`写入数据 + checksum -> 存储 -> 读取 -> 校验 -> 发现/纠正`。

## 5. Minimal Code：最小示例
```java
CRC32 crc = new CRC32();
crc.update(bytes);
System.out.println(crc.getValue());
```

## 6. Observe：先预测，再运行
先计算原数据 CRC，再翻转一个字节并重新计算。

## 7. Modify：只改一个有意义的条件
把校验算法从 CRC32 换成 SHA-256，比较用途：防误检与防篡改不同。

## 8. Exercise：独立完成
实现 `withChecksum(byte[] data)`，返回数据和校验值；读取时先校验再返回。

## 9. Real Usage：联系 Java 与工程实践
备份、下载校验、日志归档需要完整性策略；安全签名需要另外的密码学机制。
