# 交换空间、缺页与替换策略

## 1. Scenario：从一个具体问题出发
物理内存不足时，系统开始换页，服务延迟突然上升。

## 2. Why：为什么这个问题值得系统理解
超越物理内存的机制提供更大地址空间，但错误替换策略会带来抖动。

## 3. Concept：核心概念
缺页处理把缺失页调入；替换策略决定移除哪页。LRU 利用历史，时钟算法近似 LRU；脏页需要写回。Java 程序不直接控制页替换。

## 4. Mental Model：把机制装进一张图
`访问缺失 -> 选择牺牲页 -> 写回（如脏） -> 调入新页`。

## 5. Minimal Code：最小示例
```text
访问页 P：TLB 命中？是：完成。否：查页表。缺页：选择牺牲页 -> 写回 -> 调入 P。
```

## 6. Observe：先预测，再运行
用模拟器比较 FIFO 与 LRU 在访问序列 `1,2,3,1,2,4` 下的命中数。

## 7. Modify：只改一个有意义的条件
把序列重复一次或加入脏页标记，观察命中与写回变化。

## 8. Exercise：独立完成
实现一个标记为“教学模拟”的页替换器，支持 FIFO 和 LRU，并输出命中、缺失与写回。

## 9. Real Usage：联系 Java 与工程实践
分析数据库缓存、JVM GC 和容器内存压力时，先避免让工作集超过可用内存。
