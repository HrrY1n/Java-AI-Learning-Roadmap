# 分布式系统与 NFS/AFS 的核心取舍

## 1. Scenario：从一个具体问题出发
客户端缓存的文件在服务器端更新后，何时看到新版本？

## 2. Why：为什么这个问题值得系统理解
分布式文件系统必须在性能、一致性和故障恢复之间折衷。

## 3. Concept：核心概念
NFS 侧重无状态服务器和幂等操作；AFS 用整文件回调和会话语义。RPC 封装远程调用，但要处理超时、重试和部分失败。

## 4. Mental Model：把机制装进一张图
`客户端缓存 -> 协议请求 -> 服务器状态/回调 -> 一致性窗口`。

## 5. Minimal Code：最小示例
```java
// 教学示意：远程调用要处理超时和重试
// rpc.call("read", path, timeoutMs)
```

## 6. Observe：先预测，再运行
在纸上画时间线：客户端缓存文件版本 v1，服务器已更新到 v2。NFS 属性缓存到期前、AFS 回调到达前，客户端分别会读到什么？标注两套语义（轮询有效期 vs 主动回调）在时间线上的差异。

## 7. Modify：只改一个有意义的条件
把客户端的读请求提前或延后一分钟，重画时间线，观察“读到旧值”的窗口如何变化；再思考服务器崩溃重启对无状态（NFS）与有状态（AFS 回调）两种设计的不同影响。

## 8. Exercise：独立完成
设计一个 NFS/AFS 对照表：服务器状态、缓存单位、一致性语义和崩溃恢复。

## 9. Real Usage：联系 Java 与工程实践
对象存储、共享文件系统和分布式缓存都涉及类似取舍。
