# 操作系统如何虚拟化 CPU 与内存

## 1. Scenario：从一个具体问题出发
多个 Java 程序同时运行，但每个进程都感觉自己连续执行。

## 2. Why：为什么这个问题值得系统理解
操作系统通过 CPU 虚拟化和内存抽象，让程序无需直接管理硬件。

## 3. Concept：核心概念
进程是运行中的程序抽象；系统调用进入内核；受限直接执行让用户程序高效运行，同时把特权操作交给 OS。OS 通过时钟中断和上下文切换实现分时。

## 4. Mental Model：把机制装进一张图
`进程 = 地址空间 + 执行上下文 + OS 管理的数据结构`。JVM 是一个用户态进程。

## 5. Minimal Code：最小示例
```text
用户程序 -> 系统调用 -> 内核 -> 返回用户态
```

## 6. Observe：先预测，再运行
查看本机 Java 进程 PID，再读取其退出码；不直接访问内核数据。

## 7. Modify：只改一个有意义的条件
同时启动两个简单 Java 进程，观察它们互不共享堆但可能竞争 CPU。

## 8. Exercise：独立完成
解释为什么 Java 线程崩溃不一定会结束整个 JVM，而本地库崩溃可能影响进程。

## 9. Real Usage：联系 Java 与工程实践
理解容器资源限制、服务崩溃恢复和线程池调度时，需要分清 JVM 与 OS 层。
