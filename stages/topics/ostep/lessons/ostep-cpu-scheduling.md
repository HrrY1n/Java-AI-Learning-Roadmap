# CPU 调度：FIFO、SJF、RR 与多级反馈

## 1. Scenario：从一个具体问题出发
短任务排在长任务后面，响应很慢；轮转又可能增加总时间。

## 2. Why：为什么这个问题值得系统理解
调度必须同时考虑吞吐、周转、响应和公平，无法用单一指标评价。

## 3. Concept：核心概念
FIFO 顺序执行；SJF/STCF 优化周转但需要预知长度；RR 用时间片优化响应；MLFQ 用历史行为动态调整优先级。

## 4. Mental Model：把机制装进一张图
调度器在就绪队列中选择下一个任务；不同指标会偏好不同策略。

## 5. Minimal Code：最小示例
```java
record Job(String name, int arrive, int burst) {}
// FIFO：按到达顺序运行到结束；SJF：最短优先；
// RR：每次最多运行 quantum，用完排回队尾。
// 指标：周转 = 完成 - 到达；响应 = 首次运行 - 到达。
```

## 6. Observe：先预测，再运行
作业 A(8)、B(4)、C(1) 同时到达，RR 时间片为 4。先手算三种策略每个作业的完成、周转和响应时间（例如 RR 中 C 首次运行要到第 8 个时间片），再运行模拟器核对：FIFO 平均周转 11.0、SJF 6.33、RR 10.0；平均响应 FIFO 6.67、SJF 2.0、RR 4.0。指标是作业模型上的定义，不是真实 OS 调度测量。

## 7. Modify：只改一个有意义的条件
把时间片从 4 改成 1，观察响应时间与上下文切换次数的变化；或给作业加上不同到达时刻，观察 SJF 在真实到达序列下不再最优。

## 8. Exercise：独立完成
为三种策略实现 `schedule(jobs, quantum)`，输出每个任务的开始、完成、周转和响应时间；不得声称是真实 OS 数据。

## 9. Real Usage：联系 Java 与工程实践
线程池大小、批处理窗口和延迟敏感服务都需要理解调度指标。
