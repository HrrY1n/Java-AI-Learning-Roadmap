# 文件系统实现、FFS 与日志结构

## 1. Scenario：从一个具体问题出发
大量小文件占用的空间比文件内容本身更多；顺序写盘的设计减少磁头移动。

## 2. Why：为什么这个问题值得系统理解
文件系统要在容量、查找速度、局部性、崩溃恢复和吞吐之间取舍。

## 3. Concept：核心概念
经典 UNIX 文件系统用 inode 与多级索引；FFS 通过柱面组改善局部性；LFS 将写入缓冲为顺序段并做垃圾回收。

## 4. Mental Model：把机制装进一张图
`目录 -> inode -> 直接/间接块 -> 数据块`；布局策略影响连续性。

## 5. Minimal Code：最小示例
```text
读 /docs/a.txt：查目录项 -> inode -> 数据块
```

## 6. Observe：先预测，再运行
计算“一个 1KB 文件 + 一个目录项 + 一个 inode”的最小占用趋势。

## 7. Modify：只改一个有意义的条件
把文件数量从 1 增加到 1000，比较元数据开销占比。

## 8. Exercise：独立完成
设计一个教学型简易文件系统对象模型：inode、目录项和数据块；不要求真实磁盘操作。

## 9. Real Usage：联系 Java 与工程实践
数据库表空间、对象存储和日志目录都受文件系统布局影响。
