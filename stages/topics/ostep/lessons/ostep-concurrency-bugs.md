# 并发缺陷、死锁与事件循环

## 1. Scenario：从一个具体问题出发
两个线程各自持有对方需要的锁，程序永久卡住。

## 2. Why：为什么这个问题值得系统理解
并发缺陷分为原子性、顺序、死锁等问题；修复必须针对缺陷类型。

## 3. Concept：核心概念
死锁需要互斥、持有并等待、不可剥夺和循环等待。事件循环避免部分锁竞争，但阻塞调用会破坏整个循环。

## 4. Mental Model：把机制装进一张图
`获取锁 A -> 获取锁 B` 与相反顺序同时存在即危险。

## 5. Minimal Code：最小示例
```java
// 危险示意：不要在真实代码中这样写
// T1: lock(a) -> lock(b)
// T2: lock(b) -> lock(a)
```

## 6. Observe：先预测，再运行
阅读上面 Minimal Code 的死锁示意：先预测两条锁获取序列在什么交错下互相卡住，再把 `T1: lock(a) -> lock(b)` 与 `T2: lock(b) -> lock(a)` 的时序写在纸上。不要运行会卡死的示例。

## 7. Modify：只改一个有意义的条件
统一加锁顺序或使用 `tryLock` 超时，比较两种预防策略。

## 8. Exercise：独立完成
给一个双资源转账场景设计锁顺序，并解释为什么只靠 `volatile` 不够。

## 9. Real Usage：联系 Java 与工程实践
支付、库存和缓存刷新涉及多个资源时必须设计锁顺序与超时。
