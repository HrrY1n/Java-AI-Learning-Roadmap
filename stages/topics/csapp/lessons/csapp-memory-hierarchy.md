# 存储层次与缓存友好访问

## 1. Scenario：从一个具体问题出发
遍历大矩阵时，先访问行和先访问列的性能差距可能很大。

## 2. Why：为什么这个问题值得系统理解
寄存器、缓存、内存和磁盘速度不同。连续访问更容易利用空间局部性。

## 3. Concept：核心概念
缓存以块为单位保存最近访问的数据；时间局部性和空间局部性决定命中概率。Java 对象布局由 JVM 决定，数组基础类型通常比逐个对象引用更紧凑。

## 4. Mental Model：把机制装进一张图
`寄存器 -> L1/L2/L3 -> 主存 -> 磁盘`。缓存命中不是语言保证，而是趋势。

## 5. Minimal Code：最小示例
```java
long rowMajor = 0;
for (int r = 0; r < rows; r++)
    for (int c = 0; c < cols; c++)
        rowMajor += matrix[r][c];
```

## 6. Observe：先预测，再运行
先预测行遍历与列遍历哪个更可能连续，再运行源码并记录两种访问模式的时间。

## 7. Modify：只改一个有意义的条件
把矩阵边长从 512 改成 1024，观察差异是否放大；不要把一次测量当作通用结论。

## 8. Exercise：独立完成
解释为什么不能仅凭单次 `System.nanoTime()` 断言缓存收益，并设计一个更公平的观察流程。

## 9. Real Usage：联系 Java 与工程实践
大数据结构、批量计算和集合选型时考虑局部性；避免为了猜测缓存而破坏代码正确性和可读性。
