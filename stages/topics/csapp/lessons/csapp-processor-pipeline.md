# 指令集与流水线：为什么同一段代码不等于同一段时间

## 1. Scenario：从一个具体问题出发
两个逻辑等价的循环在不同 CPU 上耗时不同。

## 2. Why：为什么这个问题值得系统理解
现代 CPU 取指、译码、执行、访存和写回通常流水线化；分支、依赖和访存都会影响吞吐。

## 3. Concept：核心概念
ISA 定义软件可见指令与状态；微架构实现流水线。流水线需要处理数据冒险、控制冒险和异常。CSAPP 的 Y86-64 是教学 ISA，不是真实商用 CPU。

## 4. Mental Model：把机制装进一张图
把指令执行拆成流水段；下一条指令在前一条未完成时进入前面的阶段。

## 5. Minimal Code：最小示例
```text
取指 -> 译码 -> 执行 -> 访存 -> 写回
```

## 6. Observe：先预测，再运行
看两段 Java 循环的字节码；不要声称从字节码直接得出真实 CPU 周期。

## 7. Modify：只改一个有意义的条件
改变分支频率或数组大小，观察运行时间趋势；明确这受 JIT、CPU、内存和 OS 调度影响。

## 8. Exercise：独立完成
解释 ISA 与微架构的区别，并举例说明流水线冒险为什么不能靠 Java 源码直接推断。

## 9. Real Usage：联系 Java 与工程实践
阅读性能分析工具和 JIT 日志时，用微架构解释趋势，而不用伪精确周期数下结论。
