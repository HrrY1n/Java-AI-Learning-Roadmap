# 指令集与流水线：为什么同一段代码不等于同一段时间

## 1. Scenario：从一个具体问题出发
两个逻辑等价的循环在不同 CPU 上耗时不同。

## 2. Why：为什么这个问题值得系统理解
现代 CPU 取指、译码、执行、访存和写回通常流水线化；分支、依赖和访存都会影响吞吐。

## 3. Concept：核心概念
ISA 定义软件可见指令与状态；微架构实现流水线。流水线需要处理数据冒险、控制冒险和异常。CSAPP 的 Y86-64 是教学 ISA，不是真实商用 CPU。

## 4. Mental Model：把机制装进一张图
把指令执行拆成流水段；下一条指令在前一条未完成时进入前面的阶段。

## 5. Minimal Code：最小示例
```text
教学模拟（5 段流水线，Y86-64 风格，仅示意非真实时序）：
指令 1: mrmovq 0(%rbx), %r8   ; 从内存读入 r8
指令 2: addq %r8, %rax        ; 依赖指令 1 的结果

周期:      1   2   3   4   5   6   7
指令 1:    F   D   E   M   W
指令 2:        F   D   --  E   M   W    ; D 段多停一拍（load/use 冒险插入气泡）
```
`--` 表示流水线气泡：指令 2 必须等指令 1 在访存段写出 `r8`，这一拍就是冒险代价。

## 6. Observe：先预测，再运行
先在纸上把上面的流水线表推到第 8、9 周期，预测指令 3（不依赖任何结果）会被排在哪些段；再做一个可选的分支实验：对 100 万个整数求和，数组先升序排序再遍历与保持随机顺序各测 10 次，记录区间而不是单次值。分支预测是 CPU 微架构行为，不是 Java 规范保证，结论只谈趋势。

## 7. Modify：只改一个有意义的条件
把模拟中的依赖链加长（指令 2 改成依赖指令 2 结果的指令 3），观察气泡是否叠加；或把分支实验的分支比例（偶数判断换成恒真条件）改变，观察趋势变化。明确这受 JIT、CPU、内存和 OS 调度影响。

## 8. Exercise：独立完成
解释 ISA 与微架构的区别，并举例说明流水线冒险为什么不能靠 Java 源码直接推断。

## 9. Real Usage：联系 Java 与工程实践
阅读性能分析工具和 JIT 日志时，用微架构解释趋势，而不用伪精确周期数下结论。
