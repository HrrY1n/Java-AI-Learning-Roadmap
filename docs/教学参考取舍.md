# 教学参考取舍记录

调查日期：2026-10-29。本文件记录本次升级中真正影响设计决策的外部参考，每条只保留"借鉴什么、原仓库怎么实现、为什么适合本仓库、在哪里落地"。路线级校准见 [参考路线审计](参考路线审计.md)。

许可证已核实：Exercism Java 为 MIT；JavaGuide 为 Apache-2.0；gs-rest-service 与 spring-petclinic 为 Apache-2.0；vscode-java-pack 为 MIT（其核心扩展 Language Support for Java by Red Hat 为 EPL-2.0）。本仓库只借鉴方法与机制，未复制任何教程文本、练习题面或源代码。

## Exercism Java（exercism/java，MIT）

| 决策 | 原仓库实现 | 本仓库落地 |
| --- | --- | --- |
| 说明 / 提示 / 答案三分离 | 每个练习 `.docs/instructions.md` 给需求，提示与社区解法放在 `.meta/` 与 `.approaches/`，学习者默认看不到答案 | 各阶段练习文档的"渐进提示"放正文末尾并按级别标注；预测型练习的答案放独立的 `practice/answers.md`，要求先预测再打开 |
| 需求含显式错误条件 | 说明中直接写"不同长度序列的距离应当不成立（should not work）"，边界与错误是需求的一部分，不是附加题 | 每个结构化练习包含"正常示例 / 边界示例 / 错误输入"三段，验收条件逐条列出 |
| 概念 → 练习映射 | 根 `config.json` 声明 concept 树，concept exercise 与 concepts/ 文档一一对应 | 不引入配置体系；由各 Stage README 的概念导航与 deep_dives 的"回到练习"链接承担同样关系 |

不采纳：Gradle 测试框架、练习规模、`.approaches/` 多解法社区机制。理由：当前阶段用 `javac`/`java` 保持透明，引入 Gradle 只为自动判题收益过低；判题需求由 `scripts/` 轻量脚本承担。

## JavaGuide（Snailclimb/JavaGuide，Apache-2.0）

| 决策 | 原仓库实现 | 本仓库落地 |
| --- | --- | --- |
| 用"递进反例"破除错误直觉 | 《Java 值传递详解》依次给出三个递进案例：改基本类型参数无效 → 方法内改数组元素可见 → 交换两个对象引用无效，每一例都先让读者误以为"引用传递"，再用输出反驳 | Stage 01 `deep_dives/04_argument_passing` 采用同一路线自写案例（先预测再运行），并保留"哪些内容延后"的分层：第一周只需要"复制的规则"，C++ 对比与设计动机放拓展 |
| 知识分层与阅读顺序 | `docs/java/` 下 `basis → collection → concurrent → io → jvm → new-features`，README 给出顺序，文章按 P0/P1 问题分层 | 本仓库 Stage README 已有 必须掌握/了解即可/暂时不用深入 三层，保持现状；deep_dives 每篇按"必须理解 / 理解原理 / 适度拓展"三层组织 |

不采纳：面试题库式罗列、JVM/集合源码深度、把"高频问题"当学习主线。理由：面试驱动适合复习期，初学主线必须由可运行的程序驱动。

## Spring 指南 gs-rest-service（spring-guides/gs-rest-service，Apache-2.0）

| 决策 | 原仓库实现 | 本仓库落地 |
| --- | --- | --- |
| 结果先行 | README 第一屏先展示最终 JSON 输出与 `?name=User` 变体，再谈初始化项目 | 每个 deep_dive 开头设"运行后你会看到什么"，先给可验证目标再讲概念 |
| 每步先讲 Why 再给代码 | Controller 之前先解释 REST 契约与 Jackson 自动转换的机制 | 教学模型本就要求 Scenario → Why → Concept；deep_dives 在"最小代码"前必须给出心智模型 |
| 验证即观察机制 | 第二次请求 `id` 从 1 变 2，用输出差异证明"跨请求复用同一 controller 实例" | deep_dives 的 Observe/Modify 步骤都要求预测一个可观察差异，而不是"运行成功" |

不采纳：`initial/` + `complete/` 双完整工程副本。理由：会把学习者引向"改参考实现当作业"；本仓库用 TODO 骨架 + 独立 `my_practices/` 分离练习与参考。

## VS Code Java（microsoft/vscode-java-pack，MIT + 官方文档）

| 决策 | 依据（已核对官方文档） | 本仓库落地 |
| --- | --- | --- |
| 推荐扩展收口于官方 Extension Pack | Extension Pack for Java 含 Language Support（Red Hat）、Debugger、Test Runner、Maven、Project Manager 等 | `.vscode/extensions.json` 推荐 `vscjava.vscode-java-pack`，不散装推荐 |
| 无构建工具的"未托管文件夹"模式 | 无 pom/gradle 的文件夹可直接 Open Folder 运行调试，`Java: Configure Classpath` 管理源路径 | 与"一天一包 + javac"完全兼容；[环境搭建](环境搭建.md) 说明打开哪个目录（stage 或 lesson 源码根） |
| Scanner 交互必须用集成终端 | `launch.json` 的 `console` 字段：`internalConsole` 明确 "input stream not supported"，交互程序需 `integratedTerminal`；全局默认由 `java.debug.settings.console` 控制 | `.vscode/launch.json` 提供带 `console: integratedTerminal` 的模板；[跨平台问题排查](跨平台问题排查.md) 收录"调试控制台无法输入"条目 |
| 语言服务器 JDK 与项目 JDK 分离 | `java.jdt.ls.java.home`（`java.home` 已废弃）指定扩展运行用 JDK；`java.configuration.runtimes` 映射项目 JDK，`default: true` 服务未托管文件夹 | 写入 [环境搭建](环境搭建.md) 的"用户级设置"说明，含机器路径的配置不进仓库 |
| 排障命令 | `Java: Clean Java Language Server Workspace` 重建索引；必须 Open Folder 而非单开 .java 文件 | 收入 [跨平台问题排查](跨平台问题排查.md) 的 VS Code 条目 |

不采纳：把含个人路径的 `settings.json` 提交进仓库。仓库级 `.vscode/` 只放与机器无关的推荐与模板。

## 防过度借鉴自检

以上每条落地都回答了"怎样提高学习效果"：三分离让练习保持独立思考；递进反例直击已知误区；结果先行让每课有可验证目标；JDK 基线与命令可复现消除双平台摩擦；VS Code 模板消除交互程序卡死。未引入任何新框架、新构建工具或新进度系统。
