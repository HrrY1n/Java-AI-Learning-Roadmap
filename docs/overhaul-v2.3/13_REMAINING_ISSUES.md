# 13 · V2.3 遗留问题与已知限制（诚实披露）

## 一、有意识保留现状的事项（含理由）

1. **28 门无连续正文基础课维持 7 步形态**：审计证明其 steps 与本课代码真实联动、机制缺口已逐一成文（deep03/05/06 新小节、字段遮蔽演示等）；全量重写属"为改而改"。若未来真人学习反馈显示某课仍不够，再按课补正文。
2. **`App.tsx`（~3000 行）与 `styles.css` 不拆分**：V2.1/V2.2/V2.3 三轮评估均为低风险纯重构、无用户价值；本轮零生产代码变更是有意决策（独立审查确认 `web/src` 零 diff）。
3. **building 专题两项 P2 呈现打磨**：单课阅读页对薄课无"待扩写"标记、模块筛选"已上线"标签略乐观——数据层标注诚实（审查确认），属视觉打磨，留待有 UI 需求时统一处理。
4. **E2E 门禁覆盖面扩展**：CI 目前只对 preview 跑 `core.spec.ts`（21 用例）；其余 48 用例仅本地 `CI=1` 覆盖。扩面会让 CI 时长从 ~5 分钟明显上升（用户明确偏好精简 CI）——**需要用户决策**，建议方案：把 `v14-topics`（16 用例，本轮首跑失败集中地）加入 CI 跑面，或维持本地验证纪律（CHECKPOINT 已固化）。
5. **`menu`/`refactor` 练习散文 expected、scores 可换数组抑制硬编码**：固有设计（行为自比任务），审计判定非缺陷。
6. **day07 无结构化 Web 练习**：唯一无练习的基础课；新增练习涉及 registry/门禁联动，宜单独小轮处理。
7. **Stage 06+ 课程与其余 40 门 building 专题课**：按既定路线待后续（Stage 06 Spring Boot 为下一建设起点）；本轮已核验 building 标注诚实。
