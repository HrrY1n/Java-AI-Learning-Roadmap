# 开发环境搭建：Windows 与 macOS（Apple Silicon）

本文目标：让两台电脑都能编译、运行、调试本仓库的每个 Java 课程程序。读完并完成自检后，你只需要 [学习执行计划](../学习执行计划.md)。运行中遇到的具体报错见 [跨平台问题排查](跨平台问题排查.md)，终端与 Git 的双机协作见 [终端与 Git 双设备协作](终端与Git双设备协作.md)。

版本基线（2026-10 核对）：

- **JDK 17 及以上**即可编译运行本仓库全部 Stage 01–03 课程（课程只使用基础语法与集合/IO/Stream，未用新版本特性）。
- 本机已验证：Windows 11 + Oracle JDK 25.0.3。CI 基线：Temurin 21（Windows/macOS 运行器）。
- 已有能用的 JDK 不需要卸载或降级；只要 `java -version`、`javac -version` 能执行且版本 ≥ 17 就继续用。

## 一、JDK、JRE、JVM 到底是什么

三者的包含关系是 **JDK ⊃ JRE ⊃ JVM**：

- **JVM（Java 虚拟机）**：负责执行字节码的程序。同一个 `.class` 文件可以被 Windows 上的 JVM 和 macOS 上的 JVM 执行，这就是 Java "一次编译、到处运行"的来源。
- **JRE（运行环境）**：JVM + 核心类库（`java.lang`、`java.util` 等）。只运行别人编好的程序有 JRE 就够，但现在主流 JDK 发行版已不再单独提供 JRE。
- **JDK（开发工具包）**：JRE + 开发工具，最重要的是 `javac`（编译器）。写代码必须装 JDK。

从源码到输出经历的三个阶段，对应三个不同的角色：

```text
App.java  --javac-->  App.class（字节码）  --java-->  JVM 执行  -->  控制台输出
   你写的                平台无关               平台相关（每个系统有自己的 JVM 安装包）
```

两个常见误解：

1. **"编译通过 = 程序没问题"**。`javac` 只保证语法和类型正确；空指针、数组越界、死循环都发生在运行阶段，由 JVM 抛出。
2. **"跨平台 = 我的程序在哪儿都对"**。Java 保证的是**源码和字节码**的平台无关；文件路径大小写、换行符、控制台编码、JDK 版本这些**环境差异**仍会造成"在我电脑上是好的"。处理这些差异正是本仓库环境文档存在的原因。

## 二、安装与确认 JDK

### Windows

1. 已装的可直接用。确认方式：打开 PowerShell，执行：

   ```powershell
   java -version    # 注意输出到 stderr，这是正常的
   javac -version
   where.exe java   # 查看 java.exe 的实际位置，确认装在哪个 JDK
   ```

2. 没有安装时，任选一种：
   - `winget install EclipseAdoptium.Temurin.21.JDK`（Temurin 21，LTS）；
   - 或从 [Adoptium](https://adoptium.net/) / Oracle 官网下载安装包，安装时勾选"将 JAVA_HOME 加入 PATH"类选项。
3. 安装/修改后**新开一个终端**再验证（已打开的终端不会刷新 PATH）。

### macOS（Apple Silicon）

1. 确认：

   ```zsh
   java -version
   javac -version
   /usr/libexec/java_home -V    # 列出系统里所有 JDK 及其架构
   ```

2. Apple Silicon 必须装 **aarch64/ARM64 版本**的 JDK。用 Homebrew 安装最省事（会自动选对架构）：

   ```zsh
   brew install --cask temurin@21
   ```

   若手动从官网下载，选 "macOS / ARM64 (Apple Silicon)" 安装包。用 Intel 版虽然能通过 Rosetta 运行，但速度慢且没有必要。

## 三、JAVA_HOME 与 PATH

`PATH` 决定终端里输入 `java` 时去哪里找可执行文件；`JAVA_HOME` 是给其他工具（部分 IDE 插件、构建工具）指路的约定变量。**命令行编译运行只依赖 PATH**；建议两个都配好，一劳永逸。

Windows（图形界面方式最稳妥，避免 `setx PATH` 截断风险）：

1. `where.exe java` 找到 JDK 目录，例如 `C:\Program Files\Java\jdk-25`。
2. "编辑系统环境变量 → 环境变量"：
   - 新建系统变量 `JAVA_HOME` = 上面的 JDK 目录；
   - 编辑 `Path`，确保包含 `%JAVA_HOME%\bin`（或 JDK 的 `bin` 目录），且排在旧版本 Java 之前。
3. 新开 PowerShell 验证 `echo $env:JAVA_HOME`。

macOS（zsh）：

```zsh
# 写入 ~/.zshrc（macOS 默认 shell 是 zsh）
echo 'export JAVA_HOME=$(/usr/libexec/java_home)' >> ~/.zshrc
echo 'export PATH="$JAVA_HOME/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
echo $JAVA_HOME
```

`/usr/libexec/java_home` 会自动指向最新 JDK，避免把版本号写死在配置里。

## 四、编译并运行一个课程程序

包与目录的对应规则（`package` 声明 ↔ `com/...` 目录 ↔ FQCN）见 [README 的图解](../README.md#java-每日课程目录怎么读)，这里只给动作。以 Stage 02 第一天为例：

PowerShell：

```powershell
Set-Location stages/stage02_java_oop/existing_course/day01_class_object
javac -encoding UTF-8 -d out com/javaroadmap/stage02/day01classobject/App.java com/javaroadmap/stage02/day01classobject/Student.java
java -cp out com.javaroadmap.stage02.day01classobject.App
```

zsh：

```zsh
cd stages/stage02_java_oop/existing_course/day01_class_object
javac -encoding UTF-8 -d out com/javaroadmap/stage02/day01classobject/App.java com/javaroadmap/stage02/day01classobject/Student.java
java -cp out com.javaroadmap.stage02.day01classobject.App
```

两个平台命令**只差 `Set-Location` 与 `cd`**，其余完全一致。三个要点：

- `-encoding UTF-8`：告诉 javac 源文件是 UTF-8。这是必须的，否则中文注释在 Windows（默认 GBK）下会编译报错或乱码。
- `-d out`：把生成的 `.class` 放进 `out/`。它是产物不是源码，已被 `.gitignore` 忽略，可随时删除。
- `java -cp out FQCN`：`-cp`（classpath）告诉 JVM 去哪里找字节码；参数必须是**完整类名**，不是文件名。写 `java App` 或 `java com/.../App` 都会报 `ClassNotFoundException` 或"找不到主类"。

## 五、VS Code 配置

仓库已内置（克隆即生效）：

- `.vscode/extensions.json`：打开仓库时 VS Code 会推荐 **Extension Pack for Java**（含 Language Support for Java by Red Hat、Debugger for Java、Test Runner、Project Manager），点安装即可。
- `.vscode/launch.json`：调试模板，`console` 已设为 `integratedTerminal`——**Scanner 交互程序必须用集成终端**，默认的 Debug Console 不支持键盘输入。
- `.vscode/settings.json`：只放与机器无关的项目设置。

需要你在**用户级设置**（不是仓库文件，因含机器路径）里做的，通常只有一件事：让扩展知道用哪个 JDK。命令面板（`Ctrl+Shift+P` / `Cmd+Shift+P`）搜 "Preferences: Open User Settings (JSON)"，加入：

```jsonc
{
  // 扩展（语言服务器）运行用的 JDK；java.home 是旧拼写，已废弃
  "java.jdt.ls.java.home": "C:/Program Files/Java/jdk-25",   // macOS 例: "/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home"
  // 项目编译运行用的 JDK 映射；default 一项服务未托管文件夹
  "java.configuration.runtimes": [
    { "name": "JavaSE-25", "path": "C:/Program Files/Java/jdk-25", "default": true }
  ]
}
```

若装的是 JDK 21，把两处 `25` 换成 `21`、`JavaSE-25` 换成 `JavaSE-21` 即可。新版扩展对语言服务器 JDK 的最低要求会随版本提高，遇到提示按提示升级即可；只有一个较新 JDK 时两者天然满足。

**打开方式很关键**：用 "Open Folder" 打开仓库根目录（或某个 stage 目录），不要单独双击打开一个 `.java` 文件——扩展需要项目上下文才能建立索引。每课目录就是它自己的源码根，扩展会自动识别其中的 `com/` 结构，点 `main` 上方的 `Run | Debug` 小字即可运行/断点调试。

仓库级设置与用户级设置的分工：`.vscode/` 里提交的是"所有机器都应该一样的项目配置"；含本机路径、个人习惯的放用户级设置。这样两台电脑同步仓库时不会互相覆盖。

## 六、IntelliJ IDEA（辅助选择）

仓库 README 与各 Stage README 的命令行说明同样适用于 IntelliJ：把包含 `com/` 的课程目录标记为 Sources Root 后即可点击 `main` 旁的绿色三角。`.idea/`、`*.iml` 已被 `.gitignore` 忽略，不会同步到另一台电脑。两台电脑不必统一用同一款 IDE；本仓库所有验证脚本只依赖 JDK。

## 七、中文输出与编码（Windows 重点）

课程统一 UTF-8。JDK 18 起 JVM 默认 `file.encoding=UTF-8`（JEP 400），配合 `javac -encoding UTF-8`，源码读写天然一致。唯一常见的乱码点是 **Windows 控制台显示**：老式 cmd/PowerShell 控制台代码页可能是 GBK（936）。处理：

- 优先用 **Windows Terminal**（Windows 11 默认），显示 UTF-8 无需配置；
- 或在会话里执行 `chcp 65001` 切换代码页后再运行程序。

macOS 终端原生 UTF-8，通常无此问题。更多乱码场景见 [跨平台问题排查](跨平台问题排查.md)。
