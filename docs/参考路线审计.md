# 参考路线审计

审计日期：2026-08-13

本文件记录外部成熟项目对本仓库路线的校准。只吸收能力边界、学习顺序和工程证据，不复制大段内容，不把某个仓库的工具栈直接变成本路线的必修清单。

## 审计结论

1. 完整知识地图必须比当前执行路径广；Backend 全图、Java 面试图和 Agent 生产图不能串成投实习前的单线课程。
2. Java 实习主线应先形成可运行项目 A，再在投递期深化并发/JVM、数据库缓存、部署和系统设计。
3. Python 只学到能独立交付 AI Service 的深度；LLM/RAG/Agent 依次建立真实调用、检索评测和可靠工作流。
4. Principle 优先于 Framework：每层至多选择一个主实现，其他项目只用于比较边界。

## 对当前仓库的直接影响

- 保留 14 Stage 作为完整 Knowledge Map，新增 [学习执行计划](../学习执行计划.md) 作为唯一 Execution Path。
- 把 Java 实习 Gate 与 AI/复合岗位 P0 分开；不再要求先完成 Python、RAG、Agent 才能投 Java 实习。
- 项目 A 采用单体优先，先完成业务闭环，再补容器、CI、观测和系统设计；微服务与 Kubernetes 留在 P2。
- 项目 B 保留 Python RAG/评测主实现；Spring AI 只在 Java 侧有明确价值时做 P1 实验。
- Agent 阶段确有持久状态工作流时默认 LangGraph；Agents SDK 与其他生态只用于比较 manager/handoff、state、checkpoint、HITL、guardrails 与 tracing 等概念。
- 所有外部路线只能改变计划和验收标准，不能改变 [真实学习进度](../真实学习进度.md) 中的学习状态。
