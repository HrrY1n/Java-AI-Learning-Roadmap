# 05 · 重要设计决策记录

> 记录「为什么这样做」而非「做了什么」。每条含：决策 / 理由 / 被否决的替代方案。

## D1 · 审计采用 6 分片独立子代理 + 实测验证

**决策**：并行只读子代理分片审计，要求对可疑 Java 结论实际编译运行核对。
**理由**：45 主线课 + 91 专题节 + 全部源码无法单上下文深读；实测（javac/java/jshell）把「看起来对」升级为「验证过」。基线测试先行，保证后续改动有回归底线。
**否决**：单代理顺序审计（上下文不可行）；只静态读码（无法发现 P0-1/P0-2 这类运行时矛盾）。

## D2 · 不重写教学资产，只修点位与接线

**决策**：19 篇 deep-dive、稳定 ID 契约、learning-store、core.spec.ts、verify_manifest 列为 A 级不动资产；改动集中在错误点位、顺序、接线、缺口补课。
**理由**：审计证明这些资产实测零偏差且结构符合教学模型；重写只会引入回归风险与「为工作量而工作量」。
**否决**：按 14 步模板机械重建每门课（任务书明确禁止无意义同构）。

## D3 · Stage03 练习接入走既有 S 前缀契约而非扩正则

**决策**：`stage03 practice/predict_and_modify.md` 题号 A1→S03A1 等改名，新建 `web/content/predictions/stage03.json`，走 `--update-registry` 登记。
**理由**：build.mjs 的 ID 正则 `/^((?:S\d{2})?[AB]\d+)/` 会把裸 `A1` 解析成与 Stage01 撞号；S02 已确立 `S02` 前缀模式；改正则会放宽全局约束、破坏契约清晰性。
**否决**：修改正则给 Stage03 开特例（契约复杂化，违背「显式登记」哲学）。

## D4 · learning-store 只加「向前宽容」，不改 schema、不做迁移

**决策**：`fields()` 对未知字段从硬拒绝改为「透传保留」，`schemaVersion` 检查与全部值域校验保持不变。
**理由**：P0-5 的风险方向是「未来加字段把老用户打回内存模式」；透传保留使旧版本代码读新快照不崩（未来演进的安全垫），且**今天**不改变任何被接受/拒绝的数据（现有测试语义需复核：仅当未知字段属于未来版本时才出现差异）。任务书红线「不擅自迁移用户数据」完整保留。
**否决**：实现 v1→v2 迁移函数（无人需要，属过度设计）；保持现状（P0 风险留存）。
**补充约束**：若现有测试明确断言「未知字段报错」，改为区分「当前版本字段集合内缺失」与「未知额外字段」两种错误。

## D5 · building 三专题维持 building 状态

**决策**：csapp/ostep/network 不因本次迭代转 published。
**理由**：审计实测单节深度（1.2-1.8k 字符）与代码课覆盖率（2/12-6/17）远低于已发布线（2.5-4.6k、含双实验）；虚报发布违反诚实性纪律。门禁测试本身已防止「模块级 published 冒充全书建成」。
**否决**：批量扩写到发布线（预算内做不到 43 节精品质量，宁缺毋滥）。

## D6 · 新课程只加 2 门，其余缺口用小改与路标

**决策**：新增 `s02-static-lifecycle` 与 stage01 `day07-numeric-types` 两门 foundation 课；Optional/Comparator/List.of/PECS 以「项目迁移/深化路标」形式写入现有课。
**理由**：这两处是概念断档（后续课默认已知却从未教过），值得整课；其余缺口在深化课或后续阶段有自然归宿，整课会造成重复。
**否决**：为全部 10+ 缺口各开新课（重复与维护负担）；全部塞 deep-dive（foundation 断档应在主线可发现）。

## D7 · S02 src 参考代码「反面教材标注」而非重写

**决策**：deep dive 06 README 增加对照段，显式把 `setScore` 静默降级与 Service println 标注为「故意的旧风格，完成练习后回头 review」。
**理由**：该代码在 verify_manifest 有输出断言（改行为需同步断言且牵动练习 note）；教学价值在于「对照 review」本身，练习「指出参考实现一个可改进点」恰好承接。
**否决**：直接改 setScore 抛 IAE（需同步 manifest/练习/README 三处断言，收益低于标注）。
