# 跨平台问题排查手册

收录初学阶段真实高频的环境与运行问题。每条按 **现象 → 原因 → 验证命令 → 修复 → 如何避免** 组织，命令区分 PowerShell 与 zsh。环境安装问题先看 [环境搭建](环境搭建.md)，Git 相关见 [终端与 Git 双设备协作](终端与Git双设备协作.md)。

> 读错误信息的通用顺序：**第一行**的异常类型和消息最重要（如 `ArrayIndexOutOfBoundsException: Index 4 out of bounds`）；往下找**第一个包含你自己类名**的行，就是出错代码的位置。把这两处读明白，大多数问题不需要搜索。

## 1. `'java' 不是内部或外部命令` / `command not found: java`

- **现象**：终端里执行 `java -version` 报找不到命令。
- **原因**：JDK 的 `bin` 目录不在 `PATH` 里，或装完 JDK 后没有重开终端。
- **验证**：PowerShell `where.exe java`；zsh `which java`。无输出即不在 PATH。
- **修复**：按 [环境搭建 第三节](环境搭建.md#三java_home-与-path) 配置 PATH；改完**新开终端**再试。
- **避免**：装 JDK 后立刻执行 `java -version` 形成习惯；任何 PATH 改动都重开终端。

## 2. `javac` 找不到，但 `java` 能用

- **现象**：能 `java -version`，`javac -version` 却找不到命令。
- **原因**：只有运行环境没有编译器（如只装了 JRE，或 PATH 指向了某个只带 `java.exe` 的目录）。
- **验证**：`where.exe java`（或 `which -a java`）看它指向哪个目录，该目录下有没有 `javac`（Windows）/`javac` 可执行文件。
- **修复**：安装完整 JDK 并让 PATH 优先指向它的 `bin`（见环境搭建）。
- **避免**：始终安装 JDK 发行版（Temurin、Oracle JDK 等），而不是 JRE。

## 3. `UnsupportedClassVersionError`（编译运行版本不一致）

- **现象**：编译成功，运行报 `UnsupportedClassVersionError: ... class file version 65.0` 之类。
- **原因**：`javac` 和 `java` 来自**两个不同版本**的 JDK——PATH 里先找到的 `java` 比编译用的旧。新 JDK 编出的字节码旧 JVM 读不懂。
- **验证**：`java -version` 与 `javac -version` 是否一致；`where.exe java` 看第一个结果来自哪个目录。
- **修复**：把 PATH 里新 JDK 的 `bin` 排到旧条目之前（或删掉旧条目），重开终端。
- **避免**：一台机器保留多个 JDK 时，用 `java.configuration.runtimes`（VS Code）管理映射，终端 PATH 只放一个主版本。

## 4. `ClassNotFoundException` 或 "找不到或无法加载主类"

- **现象**：`javac` 成功，`java` 阶段报找不到类。
- **原因**（按概率排序）：① 参数写成了文件路径或类名，而不是 FQCN——必须是 `java -cp out com.javaroadmap.stage01.day01outputvariable.App`；② 当前目录不对，`-cp out` 里的 `out` 解析到了别的位置；③ 源文件的 `package` 声明与目录不一致，编出来的 `.class` 不在你以为的包里。
- **验证**：`ls out`（zsh）/ `Get-ChildItem out`（PowerShell）确认 `.class` 存在且按 `com/...` 目录分层；对照源文件第一行 `package ...`。
- **修复**：回到包含 `com/` 的课程目录再运行；用 FQCN；包声明与目录保持逐级一致。
- **避免**：把"进入课程目录 → javac → java FQCN"当作固定三步（见 [环境搭建 第四节](环境搭建.md#四编译并运行一个课程程序)）。

## 5. "在类 App 中找不到 main 方法"

- **现象**：运行报 `Main method not found in class App`（JDK 24 及以前）。
- **原因**：入口签名不完整。传统硬性要求是 `public static void main(String[] args)`；参数类型必须精确（写成 `String args` 缺 `[]`、或 `int[] args` 都不行）。注意 JDK 25 起放宽了 `public`/`static` 要求（JEP 512），但 `String[]` 参数与 `void` 仍是硬要求。
- **验证**：对照签名逐词检查；`args` 参数名可以换，类型不能变。
- **修复**：改回标准签名 `public static void main(String[] args)`——它在所有版本都可运行。
- **避免**：理解签名每部分的作用（Stage 01 deep dive `01_main_and_jvm` 有逐词拆解），而不是背模板。

## 6. 改了代码但运行结果没变

- **现象**：明明修改了代码，输出还是旧的。
- **原因**：最常见是**文件没保存**（VS Code 默认未开自动保存时，`javac` 编译的是磁盘上的旧内容）；其次是运行了另一个目录里编译出的旧 `out/`。
- **验证**：终端里 `cat`/`Get-Content` 打开源文件看最后一行是否是你的新代码。
- **修复**：保存（`Ctrl+S` / `Cmd+S`）后重新 `javac`；或开启 VS Code 的 `File → Auto Save`；删掉 `out/` 重编译最干净。
- **避免**：把"保存 → 重新编译 → 运行"当成一次完整的运行动作；对输出怀疑时先怀疑旧字节码。

## 7. `编码GBK的不可映射字符` / 中文乱码

- **现象**：编译报 GBK 编码错误（Windows），或程序输出的中文是乱码。
- **原因**：Windows 中文系统控制台默认代码页是 GBK。javac 不带 `-encoding` 时按 GBK 读 UTF-8 源文件，就会报错；运行输出方向相反时中文显示成乱码。JDK 18 起 JVM 内部默认已是 UTF-8，问题集中在终端显示层。
- **验证**：PowerShell 执行 `[Console]::OutputEncoding` 查看当前编码；`chcp` 查看代码页（65001=UTF-8）。
- **修复**：编译永远加 `-encoding UTF-8`（本仓库所有文档命令都带）；显示乱码时用 Windows Terminal，或在会话里 `chcp 65001`；PowerShell 读取外部输出可设 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`。
- **避免**：所有源文件保持 UTF-8；发现乱码先分清"读源码方向"还是"显示输出方向"。

## 8. `ArrayIndexOutOfBoundsException` / `NumberFormatException` 等运行时崩溃

- **现象**：编译通过，运行中途打印一串 `Exception in thread "main" ...`。
- **原因**：这不是环境问题，是程序逻辑触发了运行时异常（数组越界、数字解析失败、空指针等）。环境排查手册只能帮你确认"不是环境"，定位要靠读堆栈：第一行是异常类型，往下第一个自己类名的行号就是出错位置。
- **验证**：按行号打开源码，检查下标计算/输入内容。
- **修复**：修复逻辑；交互输入类崩溃先检查输入是否合法（见 [Stage 01 Scanner deep dive](../stages/stage01_java_basics/deep_dives/07_scanner_input/README.md)）。
- **避免**：看到异常先读再改；`javac` 通过只说明语法正确，不说明逻辑正确。

## 9. 编译器报"找不到文件: App.java"

- **现象**：`javac com/.../App.java` 报找不到文件。
- **原因**：当前目录不对。相对路径从"你现在所在的目录"开始解析，不在课程目录里就找不到。
- **验证**：PowerShell `Get-Location`；zsh `pwd`；再 `ls`/`Get-ChildItem` 看当前目录下是否真有 `com/`。
- **修复**：先 `cd` 到课程目录（含 `com/` 的那层）再执行命令。
- **避免**：每条命令前心里确认"我现在在哪个目录"；终端提示符里的路径就是命令的解析起点。

## 10. VS Code 里 Run/Debug 不出现，或报 "Classpath is incomplete"

- **现象**：`main` 上方没有 Run/Debug 小字；或弹出 "Classpath is incomplete. Only syntax errors will be reported"。
- **原因**：① 没有用 Open Folder 打开仓库（单开一个 .java 文件没有项目上下文）；② 语言服务器工作区缓存坏了；③ 项目里混入无法识别的目录结构。
- **验证**：左下角状态栏是否有 Java 语言状态；命令面板执行 `Java: Clean Java Language Server Workspace` 后重启能否恢复。
- **修复**：用 Open Folder 打开仓库根目录或某个 stage 目录；必要时执行 Clean Workspace 命令重建索引；确认扩展包已安装。
- **避免**：始终从 "Open Folder" 进入项目；改装扩展/JDK 后重启一次窗口（`Reload Window`）。

## 11. 调试时 Scanner 无法输入（Debug Console 没反应）

- **现象**：按 F5 调试交互程序后，Debug Console 打印了提示语，但敲键盘没反应。
- **原因**：默认的 Debug Console **不支持输入**（官方文档原文 "input stream not supported"）。
- **验证**：检查 `.vscode/launch.json` 或用户设置里 `java.debug.settings.console` 的值。
- **修复**：在 launch 配置里加 `"console": "integratedTerminal"`（仓库模板已带），用下方 TERMINAL 面板输入。
- **避免**：交互程序一律用集成终端运行/调试；直接在普通终端 `java ...` 运行也可以输入。

## 12. 同样的命令在另一台电脑上行为不同（大小写 / 换行符 / 路径）

- **现象**：Windows 上正常，macOS（或 CI/Linux）上报找不到文件、脚本报 `\r` 相关错误等。
- **原因**：三个典型差异——① 文件名大小写：Windows 与 macOS 默认文件系统**不区分大小写**，Linux 区分，`app.java` 在本地能用、推到 Linux 就坏；公开类的类名必须与文件名完全一致。② 换行符：CRLF/LF 混用会让 shell 脚本报 `'bash\r': No such file or directory`，由仓库的 `.gitattributes` 统一管理。③ 路径分隔符与盘符：Java 代码里写死 `C:\...` 或 `D:/Code/...` 在 macOS 上必然失败，应使用相对路径（本仓库代码全部如此）。
- **验证**：`git ls-files | grep -i '文件名'` 检查大小写；脚本异常时 `file scripts/xxx.sh` 查看是否带 CRLF。
- **修复**：统一文件名大小写；换行符交给 `.gitattributes`（勿手工混改）。
- **避免**：代码里只用相对路径；新文件命名后用 `git status` 确认 Git 记录的大小写。

## 13. 程序"卡住"不动（其实在等输入）

- **现象**：运行菜单/猜数字程序后终端停住，像是死了。
- **原因**：`scanner.nextInt()` 在**等待键盘输入**，这是正常行为；真实死循环（条件写错）与等输入从现象上区分：等输入时光标在程序打印的提示语后面闪烁，按 `Ctrl+C` 可退出。
- **验证**：随便输入一个数字回车，有响应即是在等输入。
- **避免**：交互程序先打印提示语再读取；用脚本自动化测试时要提供输入文件（`scripts/` 的 fixtures 就是干这个的）。
