# 08 · 学习路径验证（模拟学习者 · Stage06）

> ⚠️ AI 模拟走查，不冒充真人学习效果。验证的是"链路可复现性"：命令可跟做、页面可到达、测试可跑通。

## 一、路径 A：零依赖初学路径（无 Maven 预装、无数据库、无 Docker）

模拟一名完成 Stage01–05 的学习者从 main 检出仓库：

1. **发现入口**：网站路线页 Stage 06 卡片（已发布）→ Stage06 README 导航图 → 七课顺序 + 三工程表。✅
2. **课 1 跟做**：clone 后直接 `./mvnw test`（maven-lab）——Wrapper 自动下载 Maven 3.9.9（无需预装）→ 12 测试通过。✅ 实测。
3. **课 2 跟做**：读 12 条测试与"承诺→测试"对照表 → 跑"修改一个条件"三实验（各自动红/绿）。✅ 实测（每实验均复现预期结果）。
4. **课 3 跟做**：selftest 三条输出与预测一致；"修改一个条件"复现 500→应 400 的语义错位。✅ 实测。
5. **课 4–6 跟做**：`./mvnw spring-boot:run` 启动（日志三行可读）→ 课 5/6 的契约行为全部由 `./mvnw test` 自动断言 → 任务 3 的 broken 复现失败形态与文档描述一致。✅
6. **课 7 跟做**：`./mvnw test`（mybatis-lab）3 条绑定验证通过——"无数据库也能学 Mapper"。真库部分显示阻断声明而非伪通过。✅

## 二、路径 B：任务驱动路径（独立编程）

模拟学习者完成 8 个 practice 任务中的代表任务：

- 任务 4（加接口）：新建 Controller 方法 + Service 查询 + 2 条契约测试 → `./mvnw test` 全绿。✅ 语义与课 5 既有契约测试形状一致。
- 任务 6（修状态码）：answers 的验收测试跑红（200/500/500）→ 修复 Controller → 全绿，测试文件零改动。✅ 设计可验证。

## 三、发现的摩擦点（已处理/记录）

| # | 摩擦 | 处置 |
| --- | --- | --- |
| 1 | Windows 下无 `./mvnw` 执行习惯（mvnw.cmd 存在但课程命令写 ./mvnw） | 课程正文已注明"Windows 用 mvnw.cmd 或 mvn"；CI 的 bash shell 实测 ./mvnw 可用 |
| 2 | 首次 `./mvnw test` 下载 Maven+依赖耗时（分钟级） | 课程正文与 03 文档声明；CI 用 .m2 缓存 |
| 3 | Spring 测试对学习者是三层金字塔的新形态 | 课 2→4→5 递进式引入（单元→上下文→真 HTTP），无一步跨级 |
| 4 | 真库路径被阻断（Docker 纪律） | 课 7 与 07 文档如实声明 + 接入手册齐备，零依赖路径完整可用 |

## 四、结论

两条路径在"读课 → 跟做 → 任务 → 测试验收"全链路可复现；Stage06 的教学闭环（理解→预测→修改→独立实现→项目迁移）不依赖任何被阻断的环境。
