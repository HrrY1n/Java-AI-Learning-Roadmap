# 课程来源与接入

网站从仓库资产生成内容；原有 Markdown、Java 文件仍是正文和源码的唯一来源。构建前执行 `web/scripts/generate-content.mjs`，生成不提交的 `web/src/generated/catalog.json` 及 `web/public/reference/`。基础课的场景与学习动作保存在生成脚本元数据中，只补足原逐日 Java 示例缺少的教学桥梁，不复制维护原文件正文。

| `deep_dives/` | 7 课 | 直接读取各自 README 与对应 Java 示例 |

Stage 01 当前共有 16 个 Markdown 与 22 个 Java 源文件。Java 包含 6 个逐日示例、7 个深化示例、4 个控制台参考、4 个历史答案与1个猜数小项目。`my_practices/` 不读取、不写入。参考程序能运行只说明参考可运行，不属于学习者个人完成证据。

网站默认生成 13 个课程对象、4 个编程练习、8 个预测题、4 个修改题、14 个阶段、38 个来源文档与10个懒加载参考资源。来源文档包含已在课程页使用的7篇深化课原文以及平台使用、设计、架构与验收文档，是同源导航入口，不是额外课程。生成器不修改任何源课程、个人练习、真实学习进度或执行计划。

Stage 01、02、03、08、10、11、12 有实际 README；其他节点只展示原路线里的范围、前置关系与产出，不生成课程。路线的“已有材料”和学习进度的“未开始”是两种不同事实，网站同时保留。

## 数据形状

类型定义见 `web/src/content-types.ts`。

- `lessons`：稳定 ID（`day01`–`day06`、`deep01`–`deep07`）、正文、代码、包与类、相关课程/练习/预测、基础课教学动作。
- `exercises`：稳定 ID（`scores`、`calculator`、`menu`、`refactor`）、任务正文、四级提示、空白核心实现、案例、参考路径与来源说明。
- `predictions`：`A1`–`A8`，源码片段、问题、确定性答案、解释；A3 单独保存修改后的结果。
- `modifications`：`B1`–`B4`，原修改任务、相关课程、主动查看的原例路径与已知来源差异；这些题没有伪造自动判分。B3/B4 可解锁其实际控制台原例，查看同时关联相应菜单/计算器的参考使用记录。
- `stages`：原路线的范围和材料状态，原进度文档的学习状态，导航元数据补充的前置关系。
- `documents`：计划、路线、进度、Stage README、教学规则、环境与排查文档等只读原文；相对链接按 `sourcePath` 解析。
- `references`：仓库相对路径与懒加载资源 URL 的映射。主动解锁后再读取 `{sourcePath, language, content}`。

所有来源路径使用仓库相对路径。生成器在资产缺失、题目数量变化、提示结构变化或 Java 包声明缺失时失败，避免悄悄发布错位内容。计数与映射测试使用 Node 标准库，无额外解析依赖。Markdown 阅读由前端安全渲染，生成器不执行 Markdown 中的代码。

## 参考答案边界

完整历史答案、控制台参考与猜数小项目生成在独立 JSON 资源中，不进入默认课程 payload。只有明确点击解锁后才加载和展示，查看行为应该留在本地学习记录中。预测题答案因本地确定性判定需要而存在于课程数据里；这不是保密考试系统，浏览器开发者工具仍能读取答案。

原结构化练习的“文末提示”章节不会出现在普通来源文档路由中，避免绕开实验室的逐级展开流程。历史答案存在边界缺口，网站标明其参考身份，不将其当作新版结构化题目的完整验收答案。

## 审计发现与呈现策略

原课程保留，以下差异在相关题的 `note` 中解释，不自动修改源文档或个人代码。

| 位置 | 差异 | 网站处理 |
| --- | --- | --- |
| 计算器题干与 L3 | 题干要求非法输入提示后退出，L3 写“循环直到合法”；Scanner 深化课也演示重新询问 | 明确本题按题干退出策略验收，深化课为另一种交互策略 |
| 菜单题干与 L3 | 题干要求非法菜单项提示后回菜单，“只读合法0–2”可能掩盖非法项反馈 | 旁注要求不要静默吞掉非法输入 |
| 重构题的设计空间与 L3 | L3 提议 PASS_LINE 常量，题干允许参数、常量或方法归属的选择 | 标明常量只是一种方案，选择及理由由学习者保留 |
| B1 历史答案 | 声称 b 变成 double 后“其余行不变”，实际含 b 的加减乘结果显示也会变化 | 提醒逐行比较数值、类型与显示，保留开放式修改记录 |
| B2 历史答案 | 混入另一题的成绩数组数字后才修正 | 明确以 day05 当前数组 `{90,85,76,100}` 为准 |
| B3 题干与实际源码 | 题干描述 `break`，当前 MenuDemoApp 用 `return` 退出 | 提醒先读实际源码，再在自己的副本比较两者影响 |
| 历史参考答案 | 成绩统计缺空数组与方法拆分；计算器/菜单缺部分非法输入防御 | 解锁时标明历史参考不是本题全部验收实现 |

结构化案例中成绩数组是源码内数据，需要学习者分别修改自己的副本并重新编译；不会把数组字面量误当 Scanner 标准输入。重构练习和菜单会话包含语义要求，案例用于自测指导，不冒充已经实现的精确输出判题器。

## 维护与验证

从仓库根运行：

```text
node web/scripts/generate-content.mjs
node --test web/scripts/content.test.mjs
```

新增或调整 Stage 01 课程结构时，先改原资产，再调整少量关联元数据并运行测试。不要将生成 JSON 当成新课程源，不要直接编辑它，也不要将网站学习记录写回真实进度文档。

内容自动化测试覆盖源资产数量、原 Java 文本一致性、TODO 模板与提示隔离、预测与修改答案分离、关联与相对路径、参考答案懒加载、来源差异旁注、Markdown 章节分段与相对文档链接的真实存在性。另用真实 JDK 核对8题及1个修改条件的标准输出。最终执行结果见 [验收记录](validation.md)；原课程及学习管理文件没有产生修改。
