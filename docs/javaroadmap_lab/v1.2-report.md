# V1.2 内容架构升级报告

日期：2026-10-31　分支：`codex/v1.2-content-architecture`　基线：main @ `36046ee`

## 1. 审计结论（改造前事实）

1. 新增一节课 = 改仓库 Markdown/Java + 在 `generate-content.mjs` 的 5 个手工数组（foundations/deepMetadata/exerciseMetadata/lessonMap/notes）追加数据。
2. 写死 Stage 01：`stageRoot`/`exerciseSource`/`predictionSource` 常量、包名拼接、参考答案路径、`sourceHref` 两个文件名特判、App.tsx 侧栏（正在学习 01）、首页推荐链接（day03/deep02/deep07）、任务路由映射、入口数量文案。
3. 课程↔练习↔预测关系全部手工维护在 JS 数组里。
4. 课程 ID 就是学习记录（IndexedDB）的持久化键，改动 ID 即丢历史。
5. `sections()`/`javaFiles()`/`javaIdentity()`、documents 与懒加载参考机制本身可跨阶段复用。
6. 类型区分：lesson.kind、三个活动数组、A/B 前缀、referencePaths。
7. 导航：课程目录来自 catalog（天然数据驱动）；侧栏与首页是硬编码。
8. 双源维护：foundation 的教学步骤与 deep 的标题/简介在 JS，正文在仓库 Markdown。
9. 校验：有数量契约，但无全局 ID 唯一性、无关系校验（只在测试里）、无缺失文件上下文、无发布状态概念、无删除/改名防护。
10. 不改备份扩展内容：结构上安全（新增键即可），但无防护或测试证明。

## 2. 架构决策与理由

| 决策 | 选择 | 理由（对比项） |
| --- | --- | --- |
| 元数据格式 | 目录化 JSON（`web/content/`）| YAML/frontmatter 需要新解析依赖；TS 模块会同时参与前端构建。JSON 无依赖、生成器与前端都能直接消费、可用 `"$comment"` 字段携带说明 |
| 组织方式 | Stage → Module → Lesson → Practice，Module 仅为课程的组织标签 | 不制造空目录/包装对象；满足"专题"语义 |
| 内容状态 | `published / materials / draft / planned` | 与学习者的掌握状态（`真实学习进度.md`、IndexedDB）严格分离；只有 published 进入 Catalog |
| 生成器结构 | `scripts/content/{errors,load,build}.mjs` + 薄 CLI | 发现/解析/关系/校验/组装分离；`buildCatalog({repoRoot, contentRoot})` 可注入 fixture 根，测试不触碰真实内容 |
| 稳定 ID 契约 | `web/content/registry.json`（knownIds/retired/renames）+ 构建期比对 | 删除/改名必须显式登记，否则构建失败；`--update-registry` 显式登记新 ID |
| 练习题面锚点 | `statementAnchor` 唯一命中 | 取代"按数组顺序对齐 Markdown 章节"的脆弱耦合 |

## 3. Stage 01 一致性验证（重构前后）

方法：以 main@36046ee 生成的 `catalog.json` 为基线，与新管线输出做顶层键级 JSON 深比较。

- **逐字节一致**：lessons（除新增字段外见下）、exercises（除新增字段外）、predictions、modifications、documents、currentTasks、references。
- **设计内新增字段**：`stages[].contentState`、`stages[].modules`、`lessons[].stageId`、`lessons[].moduleId`、`catalog.workspace`（currentTaskRoutes + reviewPicks）。其余字段（含标题、简介、steps、代码、答案、用例、参考路径、URL 编号）全部不变。
- 数量契约保持：6 基础课 + 7 深化课 + 8 预测 + 4 修改 + 4 练习 + 14 Stage。

## 4. 学习数据与备份兼容性

- `LearningState`（schemaVersion 1）与 `learning-store.ts` 本轮**零修改**；Catalog 的新字段均为附加字段。
- 新增测试（`learning-store.test.ts`「V1.1 学习数据兼容性」组）：① 模拟 V1.1 时期导出的完整备份（阅读/草稿/提示/预测/复盘/本地 JDK 证据/参考查看）直接通过 V1.2 校验并逐字段保留；② 导出→再导入往返无损；③ V1.2 新 ID（如 `s02-oop-encapsulation`）的记录与 V1.1 旧 ID 记录在 `mergeBackup` 中共存。
- 未清空 IndexedDB、未重建初始状态、未做任何迁移。

## 5. 跨 Stage 扩展证明（`scripts/content-architecture.test.mjs`，7 项）

fixture 在临时目录组装最小仓库（14 Stage 路线 + Stage 02 课程/练习），验证：

1. Stage 02 课程自动发现，Stage/Module/包名/练习关系正确；
2. `materials` 门禁：未发布阶段的内容不进入 Catalog，registry 同步不误报；
3. 重复 ID 与非法关联构建期失败；
4. 缺失参考资源 / 缺失正文文件 → 带文件与课程上下文的明确报错；
5. 增量更新模拟：改正文/改标题/新增课程/调整顺序均保持稳定 ID 与导航关系；
6. 删除课程必须显式 `retired` 登记，静默删除构建失败；下线 ID 复现同样报错；
7. 改名通过 `renames` 显式迁移。

fixture 不进入 `web/content`，不冒充真实课程，不会发布。

## 7. 已知限制与后续建议

- 脚手架 `create-lesson.mjs` 面向 deep-dive/foundation 中最常见的 deep-dive 场景；foundation 沿用 `existing_course/dayNN` 结构，暂由指南人工描述。
- 多 Stage 发布后，首页「正在学习」侧栏取 `status === "学习中"` 的第一个 Stage；若同时有两个 Stage 处于学习中，需要下一轮引入阶段切换 UI（本次不扩充）。
- 预测/修改题 ID 仍为全局短码（A/B 前缀），新阶段按 `A{NN}{seq}` 约定扩展；如未来出现跨阶段重码需求，建议在 registry 中增加专用命名空间校验。
- `e2e/visual.spec.ts` 的 AA 扫描继续约束新增页面组件的对比度。
