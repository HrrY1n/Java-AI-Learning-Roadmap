## CI 是否会真实失败

新增 [web.yml](../../../.github/workflows/web.yml)，显式 Node24 与 Temurin25，`npm ci` 按锁安装。类型、单元、构建、完整产物或核心浏览器任一步失败会使 job 失败；没有 `continue-on-error`、重试掩盖或删减旧测试。Bash 使用 Runner 的 `-e -o pipefail`，日志 `tee` 不吞退出码。

事件为PR、main推送和手动执行。首轮实测发现分支push与PR重复运行同一核心矩阵，最终取消分支push副本，保留PR与main全部测试，单次减少约9.5个Runner分钟；原Java工作流不改。

本机可逆负向探针均已恢复，日志在 `gate-probes/`：

| 故意引入的问题 | 实际退出码 |
|---|---|
| 临时 TS 类型错误 | typecheck=2 |
| 临时 Vite 配置错误 | build=1 |
| 暂时移走编辑器 worker | check:build=1 |
| 恢复原产物后再核对 | check:build=0 |

真实远端也验证了失败链路：[首轮 macOS 失败](https://github.com/HrrY1n/Java-AI-Learning-Roadmap/actions/runs/40942304539/job/123688562496)和[第二轮 Ubuntu 失败](https://github.com/HrrY1n/Java-AI-Learning-Roadmap/actions/runs/41000873506/job/123884707341)均退出1；失败后仍上传日志、JSON、HTML、截图与 trace。已实际下载检查，不是只写上传配置。

**main 规则仍仅要求原四项 Java 检查。** 本轮只读核对规则 Active、严格最新基线、要求 PR、禁止强推/删除、空 bypass；未变更保护。网站红色状态已可用，但要让 GitHub 强制阻止合并，还需所有者按 [CI 配置说明](ci.md)追加三个准确的 `web-core (...)` 名称，保留原四项。没有把这个待配置项表述为完成。

## 成绩统计学习闭环与操作成本

Edge 使用独立验收来源，实际完成：工作台继续学习 → day05 → 成绩统计 → QA 草稿 → 保存/刷新 → L1–L4、Debug、Review → 本地运行说明 → 复盘 → 返回现场。草稿和复盘逐字保留，提示不替写代码；阶段一直为学习中。手工下载事件的浏览器控制接口未返回，未将该次操作记作手工下载验收。

生产 Chromium 自动化另完整执行了真实下载 → 读取下载字节 → 临时目录真实 JDK → 导入成功/编译失败 JSON → 重复/冲突/指纹拒绝 → 修改草稿使旧结果失效 → 复盘返回。QA 仅运行 TODO 骨架的空输出与故意语法错误，清理自身临时目录；没有替学习者实现算法。

| 日常步骤（成绩统计单个案例） | 操作成本与判断 |
|---|---|
| 课程到实验室 | 相关题目链接1次；相关概念可返回原课 |
| 写代码、保存 | 编辑自动保存，无额外“提交”动作；关闭前等已保存 |
| 取提示 | 打开一次，再按需逐级解锁；无需全部展开 |
| 运行与记录 | 下载1份 Java；自己推导并保存1份 expected.txt；修改示例文件路径并运行1条 CLI；导入生成的1份 JSON |
| 查看失败 | 实测记录保留 javac 原始 stderr/退出码及编译标签；课程 Debug 按读错→定位→假设→验证→复盘引导；未承诺自动解释所有编译错误 |
| 复盘与返回 | 自动保存理解/下一步；复盘页“返回现场”1次定位原题 |

修前说明容易诱导先 javac/java 再 CLI，共三条命令；修后推荐一条，成绩数组题不再创建 input.txt。正常/单元素/空数组仍需本人修改数组、各自推导预期并生成不同记录。一份记录成功不会自动算整题完成。

**摩擦仍然明显：** 浏览器、文件系统、终端之间往返，每轮至少下载源码、维护预期文件、运行命令、选 JSON，手机更适合阅读/预测。首次配置 JDK 和频繁修改时会成为实际成本；工具链足以用，但不是一键判题。后续可评估可信本地目录中的多案例清单与批处理、IDE 中直接运行同一 CLI、明确鉴权且只绑定回环地址的本地伴随工具。本轮均未开发，没有公开执行 Java 的服务。

## 数据安全检查

| 风险 | 本轮证据 / 行为 | 剩余边界 |
|---|---|---|
| 异步保存与离开 | 串行快照；180ms去抖；保存中 beforeunload 阻止离开，取消后保存刷新恢复；新增真实浏览器用例 | 强制关进程、系统崩溃或移动系统直接回收可能丢失尚未持久化的最后输入 |
| 两标签同时编辑 | 实际两页测试触发 revision 冲突，拒绝静默覆盖；仍可下载当前内容 | 需要分别备份、刷新、主动合并，不提供协同编辑 |
| IndexedDB 禁用/损坏 | 浏览器用例及单元均拒绝打开/校验，保留原值，不自动清空 | 物理损坏、清站点数据与长期驱逐未实测；外部备份仍必要 |
| 重复与冲突备份 | 相同证据 ID 去重；同ID不同内容取消；坏JSON/未来版本拒绝，替换先触发原数据下载 | 无法证明用户已把下载永久保存；必须保留原备份 |
| 较旧跨设备数据 / 同题代码 | 单元核对新草稿优先、另一题补入；UI提示同名内容差异并要求确认 | 按设备时间保留新版本，不维护多分支历史；时钟错误需人工对照，真实双设备未测 |
| 版本与大小 | v1 严格字段、日期、危险键、条目与10MB限额校验；未知版本拒绝 | 无虚构v2迁移；超限明确失败，不偷偷裁剪 |
| Java证据与草稿 | SHA-256同题同字节匹配；重复/冲突受控；改源码显示旧记录失效 | JSON未签名，可被用户编辑；只核对记录一致性与所列案例，不能证明独立完成或题目覆盖 |
| 断网 / 编辑器资源失败 | 当前页断网编辑保存，联网刷新恢复；Monaco资源失败提供textarea；手机默认轻量 | 无Service Worker，不保证断网冷启动；无Java语言服务器或浏览器JVM |

本轮修复了“保存失败未被捕获”这一数据风险，没有扩大数据模型。备份文件是人工迁移，不宣称云同步。实现见 [`learning-store.ts`](../../../web/src/lib/learning-store.ts)。
